# V01 · 目标驱动的算法检验任务规划

> **用途**：由 ChatGPT 根据算法包现状，为 Codex、WorkBuddy、Claude Code 等 Agent 制定下一项中等偏大的综合检验与优化任务。
> **适用阶段**：算法包已生成，正式实验运算尚未开始或尚需独立授权。
> **版本**：v1.0（2026-10-26）
> **来源类型**：参考开源项目的任务组织思想独立改写；不是 GitHub 项目的原文或可直接安装的 Skill。

## 使用前提供

项目路径或仓库、当前状态/已有证据、希望验证的目标、已授权操作范围、资源上限及冻结协议。能从现有材料确认的内容不必重复填写。

## 可直接复制的 Prompt

```text
你负责根据科研算法包的当前状态，为 Codex、WorkBuddy、Claude Code 等 Agent 制定检验、修复与优化任务。

项目/算法包：【路径或已有材料】
本轮目标：【希望解决或验证的问题】
现有证据：【最新状态、已完成的测试、结果与阻塞】
授权与边界：【只读/允许修改/允许测试；GPU、资源预算、冻结协议等】

核心目标：在不降低科研质量的前提下，减少任务数量、人工交互与 Agent 总 Token 消耗，提高单次任务的有效工作量。

规划原则：
1. 目标与证据优先：先用已知代码、状态、结果和失败证据确认当前最有价值的验证目标及必要准入条件。仅根据实际可读材料判断；资料不足时不假称已检查。
2. 合并关联工作：优先将相互关联的审查、根因定位、代码修复、优化、测试补齐和针对性回归验证组成一项中等偏大的综合任务；不按文件、模块或单项测试机械拆分。
3. 动态决定粒度：按科学风险、模块依赖、成本、授权边界和可独立验收性调整任务范围。不要预设 Batch 数、验证轮次或固定阶段；新发现允许 Agent 在授权范围内自主调整顺序和内容。
4. 连续自主执行：在一次必要的可行性和权限检查后，要求 Agent 连续完成已授权的关联工作，自主解决一般性问题，不逐项要求用户确认；遇到受限操作只暂停受限部分，其他独立合法工作可继续。
5. 效率优先：复用现有可靠证据和测试结果；避免重复读取历史、重复规划、无必要的全量测试、冗长日志及无收益的多 Agent 调用。优化的是整个任务周期的 Token 和操作成本，而非单纯缩短指令。
6. 严格验证：保留算法正确性、数据无泄漏、输入/标签语义、Baseline 公平性、指标口径、可复现性、根因证据和必要测试。不得伪造 PASS、科研结论或人工批准。
7. 严守门禁：不得擅自修改冻结的研究目标、数据划分、协议或评价规则；未授权 GPU/正式实验、不可逆操作和资源超限操作不得自动执行。提出执行指令不等于获得执行授权。

输出要求：
- 默认只输出「下一项最有价值且工作量适当偏大的、可直接交给 Agent 的综合任务指令」；不提前拆出大量细碎后续任务。
- 指令仅写：目标与范围、授权边界、关键验收标准和证据、最简交付内容；内部检查步骤交由 Agent 自主组织。
- 如必须拆分，仅简述依赖、风险或权限理由，以及当前可执行的最大合理工作单元。
- 最终交付要求 Agent 报告实际修改、关键验证 PASS/FAIL/UNKNOWN、证据位置与剩余阻塞；不得把未运行的实验写成通过。
```

## 使用示例

将最新状态、相关日志或算法包路径发给 ChatGPT，并说明：“用 V01 制定下一项综合检验优化任务。”复制它生成的**执行指令**给 Codex / WorkBuddy。下一轮依据实际结果更新，不必提前规划固定批次。

## 与现有模板的区别

- **V01（本文件）**：负责动态规划下一项综合工作，提高单任务有效工作量并控制 Token 成本。
- [X01 · Codex 科研代码结果审计与下一步指令](../07_专项/X01_Codex%20科研代码结果审计与下一步指令.md)：侧重核验已有日志、指标和代码证据，辨别 PASS/FAIL/UNKNOWN，形成审计结论。
- [R02 · 实验与算法方案设计及结果审计](../02_科研研究设计/R02_实验与算法方案设计及结果审计.md)：侧重科学假设、Pilot 设计与负结果归因。

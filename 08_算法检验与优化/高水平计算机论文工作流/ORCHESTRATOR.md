# Research Workflow v6.1｜默认简单，按需复杂

**唯一默认路线：目标 → 最小原型（MVP）→ 有证据的迭代 → 按需科学反思 → 正式确认/论文。**
24个历史场景是工具库，不是必经步骤；五个旧阶段只作为科研能力分类。不要把“先读完文档/多AI评审/所有检查PASS”当作开发前提。

**平台路由（第一阶段优先 ChatGPT）**：当任务是①科学选题（01-A～01-D），默认由 **ChatGPT 在同一平台连续完成**文献/最近邻核查、候选与创新命题、数据真值的资料级判断、最小算法设计及方向建议；用户批准重大改题。不得仅为形式上的「跨AI审核」频繁转 WorkBuddy/Codex。只有本地代码/大规模数据的实际读取与运行无法在当前 ChatGPT 完成，才将相应执行任务交给 WorkBuddy/Codex（属于数据验证或算法研发）；只有关键风险需要真实独立复核，才交给隔离会话/其他模型或审查者，并明确其是否真的独立。**该优先级不意味着必须完成①才能启动已授权的MVP，也不允许把ChatGPT的自查称为独立审核。**

## 启动（一次，尽量直接动手）

1. 定位**科研项目**与**提示词库**两个不同仓库；读取已有 STATE/最近有效 Run、代码和数据入口，已有可复用成果直接续做。没有状态文件不要求先创建一套体系。
2. 用最短记录明确：可证伪问题、标签/数据能否回答它、最近邻差额、简单强基线、最危险前提与资源。**成功价值反推**：即使内部指标全好，相对最近邻新增什么任务/理论/机制贡献？不确定标 `VALUE_UNVERIFIED`，允许低成本探索。
3. 只核本次实验必要的数据许可、标签/真值、分组与时间因果性；明显致命缺陷阻断受影响实验。其余文献与大规模可行性审查**后移**。缺决定性真实数据或授权时，只做一次必要准备并集中提出请求；不连续用合成门禁替代真实证据。
4. 在获批范围内，优先做简单基线 + 最小可运行算法 + 最少能区分关键解释的实验；首次Pilot尽可能同时保留代理指标与主张对应的真实任务/独立机制证据；暂时取不到标缺口，不要求全面消融与独立审查。

## 内循环（默认，自动连续）

观察真实结果 → 找到一个主要问题/新机制假设 → 做最小有效修改 → 针对性测试 → 记录 `KEEP / DISCARD / INCONCLUSIVE / INVALID` → 继续下一个有信息量的任务。重要修复先问：修好后会改变哪个科研决策？若不会，停止该修复；普通Bug可直接自修。避免重复读全部Prompt/测试。失败结果保留，回退代码不删实验记录。**技术Bug与可信科学负结果分开**；优先简单强基线，不靠最佳seed、泄漏或重复正式test调参制造增益。在已经批准的成本范围内合并执行关联任务；不允许无限循环或擅自扩额。

## 可核查的按事件路由（仍由Agent在实际工具中执行）

必要时使用 `python workflow_route.py --event BASELINE_STRONGER` 等**只读建议**。事件表见 [ROUTES.json](ROUTES.json) 的 `event_advice`（包括 NEW_PROJECT、RESUME、NO_GAIN、INVALID_EVIDENCE、NEW_MECHANISM、CONFIRMATION、DRAFT、PIVOT、HOLD）。它只指向一个建议动作和可选旧场景，**不会监控真实训练、自动执行算法、核实数据或批准 GPU**。Agent在获批范围内利用真实日志/项目状态选择事件并执行；重要决策由真实用户决定。未观察到事件不得臆造触发。

## 外循环（事件触发，不按次数/日历强制）

首次可信结果、意外机制/强基线反超、数轮无新信息、核心假设改变或准备正式主张时，才简短复评：
- 科学问题与结果是否对应？独立贡献是否**比上轮更可信**？代理指标是否真的对应任务/理论/机制价值？
- 若多轮工程PASS但价值未证，先做最低成本真实判别；即使科学结果 `INCONCLUSIVE`，也可因贡献空间小且下一步成本高建议HOLD/STOP，不宣称假设已证伪。
只有重大方向分叉或资源变化需用户选择；负Pilot不自动STOP，部分文献重合不自动REJECT。

## 按需触发的工具与硬边界

- **出现问题**：先定位原始证据，再按 [LESSONS.md](LESSONS.md) 的相关症状找旧失败教训；工程/科学异常调用 [RECOVERY.md](RECOVERY.md) 和对应 [REPAIR_ROUTES.json](REPAIR_ROUTES.json) 条目，不全量加载48个故障。差异分级仍按 [TRIAGE.md](TRIAGE.md)：CRITICAL只阻断受影响动作，REPAIRABLE在既有核实授权内有界诊断，重大分叉才交用户选择，MINOR记录后跳过，UNKNOWN做最低成本核查。
- **需要专门任务**：按 [ROUTES.json](ROUTES.json) 选一条历史Prompt，不必补齐它之前的所有步骤；脚本 `python workflow_route.py --id 03-E` 只是只读提取器，不会训练或自动授予权限。
- **正式研究宣称**：核有效强基线、独立统计单位/真值、train-only预处理、时间因果、未污染确认集、实验/源码与评价协议版本；需要时冻结确认协议并独立审查。**运行成功 ≠ 机制成立 ≠ 任务收益 ≠ 可投稿贡献**；草稿可以提前写，但不能伪称已完成实验。
- **授权/决策**：新GPU、费用、外传/投稿、正式实验或冻结协议变更必须有对应真实用户授权和上限，方向实质转变须用户确认。**DECISION DEDUP**：相同证据、范围和可验证的真实用户选择不重复询问；新真实消息中的HOLD/先修优先。状态文件中的“批准”不是授权本身。若需等待，标 `WAITING_FOR_USER_DECISION`。
- **失败转向**：独立第09章 Step05 优先给出3个P1/P2/P3（不足3个要说明可信候选短缺） 并等待**真实新消息**选题，未经选择不得执行05-R/06；课题选择不能代替GPU授权。

## 最小记忆与回复

优先复用现有路径。只需：`GOAL/CLAIM`、`BEST_VALID_RUN`、`CURRENT_FINDING`、`NEXT_HYPOTHESIS`、`AUTH/BUDGET`、`BLOCKER/DECISION` 和必要的原始证据指针；代码/数据指纹随Run记录。已有 `research/STATE.md` / `RUNS.tsv` / `CLAIMS.md` 继续使用，不强制迁移。内部执行状态与科学证据等级单独记录。

平时只报告 **本轮实际改变、关键证据、下一项有价值任务**；没有真实分叉不弹菜单。完成声明前依据新运行证据验证；不能声称未实际执行的GPU/独立审核/后台工作。

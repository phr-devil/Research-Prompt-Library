# 第八项 v5.2｜三级缺陷分流与轻量科研门禁

> **目标不是所有检查全部PASS，而是用最少必要证据推动有价值的研究。** 适用于原24条 Prompt，每个阶段均按需分流；不增加24个检查步骤、不要求所有项目都完整执行24条。规则清单：[TRIAGE_POLICY.json](TRIAGE_POLICY.json)。

## 0. 先回答“问题影响哪个动作或结论？”

同一问题对**早期探索/代码实现**和**正式确认性论文主张**的严重度可能不同。先确定 `TARGET_ACTION`、原始证据、科学影响；未知 `UNKNOWN` 不自动视作致命，只做一项最便宜的鉴别。阻断必须说明**受影响的下一步是什么、为什么受影响、什么证据可以解除阻断**。未受影响的合法静态工作可以继续。

| 级别 | 什么问题属于它 | Agent 默认动作 | 用户看到的选择 |
|---|---|---|---|
| **CRITICAL（致命）** | 经证据确认的许可/权限违规、关键真值循环、确认性测试泄漏、核心结论依赖无效评价，或无法合法实施相应实验 | **禁止执行受影响的下一步**，标 `BLOCKED_CRITICAL`，保存其余合法结果 | 只提供**修复 / 修改受影响主张 / HOLD或STOP**，**不提供“直接继续该动作”** |
| **REPAIRABLE（一般）** | 文献覆盖不完整、少一个基线/消融、早期结果不稳定、Pilot未增益、独立审核暂未做等（需标局限） | `WAITING_FOR_USER_CHOICE`，给简明风险与推荐 | A 带限制继续探索/准备，B 先修复，C 缩窄目标或暂停；无需每条小问题都重复问 |
| **MINOR（轻微）** | 文案、展示、非关键可选测试、不会影响科学有效性和权限的低风险小缺陷 | **记录 `DEFERRED_MINOR` 后直接继续**；能安全顺手修则修 | 默认**不打断**，仅阶段总结时简短汇报 |

**禁用的错误做法**：因为某项非必要消融缺失就全项目STOP；把部分文献重合直接视作缺乏创新；把“Pilot没提高指标”视为造假或必然终止；反过来把污染测试集降成MINOR以强行出正结果。未知情况先核实关键事实，不无限审查。

## 1. 每个阶段提供哪些允许的选择？

- **阶段①选题**：方向有可证伪科学增量就可以由用户选定并进入最小探索，允许剩余论文补查、某个模块设计不完整。选项：**继续当前方向 / 优先补关键证据 / 调整主张**；不需要承诺科研成功。
- **阶段②Pilot**：有效负结果也是真实进度。若指标未见增益但真值与评价有效，由用户选择**限定预算继续设计或调试 / 一次诊断 / 转向或HOLD**，不强制每次Pilot必须有显著改善。
- **阶段③研发**：实现过程里一般 bug 在已批准范围内自动修复，非关键warning自动记录；若机制缺乏增益，用户可选在**原授权内有界探索**或修机制。正式确认实验仍需数据/协议合法、额外资源明确授权。
- **阶段④独立审核**：未获得外部独立审查不能宣称独立PASS，但可以选择**先写清楚未核验局限的草稿 / 等独立审查 / 先修重大问题**。Minor不必全部闭环才能起草。
- **阶段⑤论文**：轻微格式问题自动改；中等缺口允许先草拟并保留 `[VERIFY]`；正式投稿必须满足关键事实与版权/伦理要求，且作者明确批准。

## 2. 决策与记录尽量短

若存在多个缺陷，按**当前目标的最高影响级别**合并展示一次；不逐条弹窗。默认 4–8 行，2–3 个选项，有推荐理由但用户可以反选。选择“带限制继续”必须在现有 `research/STATE.md`（或等价路径）保存：`ISSUE_ID / LEVEL / TARGET_ACTION / USER_CHOICE / ALLOWED_SCOPE / LIMITATIONS / REVISIT_BEFORE / EVIDENCE_PTR`，并以**后续真实用户消息**为依据；只允许跳过对此目标不关键的检查，**不能变更 GPU/收费/正式实验/冻结协议权限**。

~~~text
【02-D · REPAIRABLE】有效Pilot暂未优于强基线；没有发现泄漏。
【建议】B：先做一次最低成本的失败归因。
A｜继续现有授权内的探索（保留无增益结论）
B｜先修复/诊断，再决定正式训练
C｜调整方向或HOLD
回复 A/B/C。
~~~

致命问题例子：

~~~text
【03-F · BLOCKED_CRITICAL】确认性test已被反复用于选模，不能继续据此宣称正式提升。
A｜修复验证协议：申请新独立确认数据/必要授权
B｜缩窄为探索性论文主张（请确认新主张）
C｜HOLD/停止该主张
~~~

## 3. 路由动作

`TRIAGE`（对**受影响目标**）→ `MINOR: DEFERRED_MINOR + CONTINUE`；`REPAIRABLE: 给一次选择 → 继续探索/先修/调整`；`CRITICAL: BLOCKED_CRITICAL` 且不得放行受影响动作。按 [RECOVERY.md](RECOVERY.md) 及 [REPAIR_ROUTES.json](REPAIR_ROUTES.json) 修根因；修复后重查原证据和严重度，不因换阶段而“自动消失”。

完成步骤的定义改为 **`READY_WITH_LIMITATIONS` 也可以成为后续探索的有效入口**，但不能用于正式已验证结论；`VERIFIED` 才能支持对应确认性声明。若只有未知信息而尚无致命证据，不应粗暴STOP：先做最便宜的核查，对高影响的**特定宣称**保持冻结。

**人工授权仍是硬边界**：用户可选研究方向和带限制继续，但 GPU、付费、外传/发布、正式实验与协议冻结调整都必须单独明确批准（动作/预算/停止条件），不能由一般 A/B/C 默认为已批。第09类 Step05 三项目用户选择门禁保留。

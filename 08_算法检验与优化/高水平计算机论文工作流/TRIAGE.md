# 第八项 v6.1｜有界自主诊断与安全风险选择复用

> **目标不是所有检查全部PASS，而是用最少必要证据推动有价值的研究。** 适用于原24条 Prompt，每个阶段均按需分流；不增加24个检查步骤、不要求所有项目都完整执行24条。规则清单：[TRIAGE_POLICY.json](TRIAGE_POLICY.json)。

**与科研判决分层**：三级缺陷分流CRITICAL/REPAIRABLE/MINOR仍用于决定**哪些动作受阻**；科研结论另记`DECISION_SCOPE=RUN|MECHANISM|CLAIM|PROJECT`，只有可靠证据支持才能扩大止损范围。工程RED、代理无增益或单个失败Run不自动推出PROJECT级科学证伪。

**风险分流≠科研项目退出**：[科研续投与止损](RESEARCH_DECISIONS.md)定义CONTINUE/REPAIR/PIVOT/HOLD或STOP的投入判断。CRITICAL只禁止受影响且无法有效执行的动作，不必阻断无关合法探索；REPAIRABLE不要求每次有性能改善；MINOR不强制修完。**负Pilot先核结果有效性与范围**，下一项实验能否改变判断及其成本是是否续投的依据；项目级HOLD/STOP与实质改题由用户确认。科研独立确认的标准不降低。

## 0. 先回答“问题影响哪个动作或结论？”

同一问题对**早期探索/代码实现**和**正式确认性论文主张**的严重度可能不同。先确定 `TARGET_ACTION`、原始证据、科学影响；未知`UNKNOWN`不自动致命，也不逐项核查；只有妨碍当前行动合法性/证据真实性或引发大额不可逆成本时，才做最便宜鉴别；其余标`DEFER_UNKNOWN`，未判断关联性先做`CLASSIFY_CURRENT_ACTION_IMPACT`而非全量核证。阻断必须说明**受影响的下一步是什么、为什么受影响、什么证据可以解除阻断**。未受影响的合法静态工作可以继续。

| 级别 | 什么问题属于它 | Agent 默认动作 | 用户看到的选择 |
|---|---|---|---|
| **CRITICAL（致命）** | 经证据确认的许可/权限违规、关键真值循环、确认性测试泄漏、核心结论依赖无效评价，或无法合法实施相应实验 | **禁止执行受影响的下一步**，标 `BLOCKED_CRITICAL`，保存其余合法结果 | 只提供**修复 / 修改受影响主张 / HOLD或STOP**，**不提供“直接继续该动作”** |
| **REPAIRABLE（一般）** | 缺少非当前必需的基线/消融、早期结果不稳、Pilot无增益；也可包括已定位且可局部修复的工程问题 | **真实授权、主张/协议/预算未变时**自动定向修复/诊断→验证→续做；其余情况才考虑选择 | 实质分叉、新风险或授权不足才问；普通Bug不逐项询问 |
| **MINOR（轻微）** | 文案、展示、非关键可选测试、不会影响科学有效性和权限的低风险小缺陷 | **记录 `DEFERRED_MINOR` 后直接继续**；能安全顺手修则修 | 默认**不打断**，仅阶段总结时简短汇报 |

**禁用的错误做法**：因为某项非必要消融缺失就全项目STOP；把部分文献重合直接视作缺乏创新；把“Pilot没提高指标”视为造假或必然终止；反过来把污染测试集降成MINOR以强行出正结果。只查影响当前行动的关键未知，不无限审查。

**科学有效性与投资价值分账**：`INVALID`＝证据或评价失效，`INCONCLUSIVE`＝证据不足，`RESEARCH_VALUE_LOW`＝下一研究投入难产生独立价值。后者不是第四级缺陷，也不是科学反证；可建议有依据的HOLD/STOP，但不得自动禁用用户获批的安全有界探索。

**修复价值**：重要修复只要能恢复必要实验能力、取得真实新观察或改变关键决定，就可在授权预算内继续；无上述收益、非科学真实性必修且成本失衡时才停止。缺真实数据时一次说明授权缺口，不用反复合成门禁冒充数据准入。

## 1. 每个阶段提供哪些允许的选择？

- **阶段①选题**：方向有可证伪科学增量就可以由用户选定并进入最小探索，允许剩余论文补查、某个模块设计不完整。选项：**继续当前方向 / 优先补关键证据 / 调整主张**；不需要承诺科研成功。
- **阶段②Pilot**：有效负结果也是真实进度。在原授权内优先自行做有判别力的最小诊断或不同机制探索；需新增预算、重大转向或项目级HOLD才请用户选择，不要求每次Pilot显著改善。
- **阶段③研发**：实现过程里一般 bug 在已批准范围内自动修复，非关键warning自动记录；若机制缺乏增益，用户可选在**原授权内有界探索**或修机制。正式确认实验仍需数据/协议合法、额外资源明确授权。
- **阶段④独立审核**：未获得外部独立审查不能宣称独立PASS，但可以选择**先写清楚未核验局限的草稿 / 等独立审查 / 先修重大问题**。Minor不必全部闭环才能起草。
- **阶段⑤论文**：轻微格式问题自动改；中等缺口允许先草拟并保留 `[VERIFY]`；正式投稿必须满足关键事实与版权/伦理要求，且作者明确批准。

## 2. 一般缺陷只问一次，条件改变才重新确认

**优先级约定**：用户明确的新选择优先于旧缓存及 MINOR 的自动继续；HOLD、先修或调整主张都需要正确响应。UNKNOWN不自动变为CRITICAL或安全PASS；相关高风险未知才做最低成本查证，其余延期；正式实验/主张/投稿保留独立门禁。

先用 `CLAIM_ID + TARGET_ACTION + 数据/协议版本 + ISSUE_ID` 定位同一风险。已有后续真实用户消息、原始证据、真实用户后续消息与本次提示词版本均可由运行环境验证，且该决策仍在 `REVISIT_BEFORE` 允许范围内，**后续步骤直接复用先前的“带限制继续”选择**，不因为换到下一个 route 再弹菜单。主张、分组、冻结协议、权限范围或风险等级改变时失效；无法确认原始真实用户消息时不可从 JSON 单独推断获批。合并同一时点的一般缺陷，不一次一项问。

`CONTINUE_LIMITED` 仅用于只读查证、获批范围内的探索、非正式草稿，**不用于正式实验、已确认科学主张或外部投稿**；后者分别核实独立证据和独立用户授权。运行器给出的建议状态不是实际权限判定。

## 3. 自动纠错与对用户的回复

**日常执行**：低风险Bug在真实授权内批量处理，不弹A/B/C、不中途发送逐次故障报告；原失败测试及受影响回归通过才称“已修复”，自动返回原任务。能保留的Run不重跑；缺验证标`NOT_RUN`。有效的科学负结果转 [RESEARCH_DECISIONS.md](RESEARCH_DECISIONS.md)，不是强行纠错。

**阶段末仅报增量**：`修了什么 | 实测验证/NOT_RUN | 受影响Run/Claim | 已恢复的任务/下一步`，通常1–3行。风险、权限、论文主张或协议需要用户决定时，集中报告影响范围和最小授权请求；没有真实分叉不要求用户回复。详见 [RECOVERY.md](RECOVERY.md)。

## 4. 决策与记录尽量短

仅**需要用户决定**且存在多个缺陷时，按当前目标的最高影响级别合并询问一次；不逐条弹窗。此类消息4–8行、2–3个选项；已授权的普通修复不显示选项。选择“带限制继续”必须在现有 `research/STATE.md`（或等价路径）保存：`ISSUE_ID / LEVEL / TARGET_ACTION / USER_CHOICE / ALLOWED_SCOPE / LIMITATIONS / REVISIT_BEFORE / EVIDENCE_PTR`，并以**后续真实用户消息**为依据；只允许跳过对此目标不关键的检查，**不能变更 GPU/收费/正式实验/冻结协议权限**。

~~~text
【仅在需用户决定时】有效Pilot尚未优于强基线；原预算已用完，追加训练需新授权。
【已有证据】该机制的当前结果有效，但不能证明整个课题失败。
A｜批准新的有界诊断预算（写明资源上限）
B｜先做不需新增授权的只读分析
C｜建议HOLD当前机制或讨论改题
~~~

致命问题例子：

~~~text
【03-F · BLOCKED_CRITICAL】确认性test已被反复用于选模，不能继续据此宣称正式提升。
A｜修复验证协议：申请新独立确认数据/必要授权
B｜缩窄为探索性论文主张（请确认新主张）
C｜HOLD/停止该主张
~~~

## 5. 路由动作

`TRIAGE`（对**受影响目标**）→ `MINOR: DEFERRED_MINOR + CONTINUE`；`REPAIRABLE: 现有授权内无新风险时有界诊断继续；否则给一次选择 → 继续探索/先修/调整`；`CRITICAL: BLOCKED_CRITICAL` 且不得放行受影响动作。按 [RECOVERY.md](RECOVERY.md) 及 [REPAIR_ROUTES.json](REPAIR_ROUTES.json) 修根因；修复后重查原证据和严重度，不因换阶段而“自动消失”。

完成步骤的定义改为 **`READY_WITH_LIMITATIONS` 也可以成为后续探索的有效入口**，但不能用于正式已验证结论；`VERIFIED` 才能支持对应确认性声明。仅有未知而无实证致命阻断不应STOP：只查当前高影响行动/主张，其他未知延期；正式确认前再补证。

**人工授权仍是硬边界**：用户可选研究方向和带限制继续，但 GPU、付费、外传/发布、正式实验与协议冻结调整都必须单独明确批准（动作/预算/停止条件），不能由一般 A/B/C 默认为已批。第09类 Step05 三项目用户选择门禁保留。


**状态分离**：程序运行的 `RUN_STATUS=COMPLETE/PARTIAL/INVALID/CRASH/BLOCKED/NOT_RUN` 与科研步骤的 `ROUTE_READINESS=VERIFIED/READY_WITH_LIMITATIONS/BLOCKED_CRITICAL/PARTIAL` 不可互相替代。引用过期的完成状态不可自动放行实验。

纯 Python `can_reuse_risk_choice()` 属于**静态辅助判定**，不连通聊天身份与权限系统；`user_message_verified=True` 必须由有能力独立核实后续消息的运行环境传入，不能从模型自己生成的 JSON、研究文件或命令行文本获得。无可信验证、用户主动改变选择或证据版本改变即不可复用。

**执行优先级（v6.1）**：从真实会话和原始证据核对授权与影响范围；可控一般缺陷的简单诊断属于日常内循环，不为此要求一轮A/B/C；需要改变论文主张、冻结评价协议、新增算力/成本或真实用户已要求HOLD时才停下选择。静态路由器返回的 `BOUNDED_DIAGNOSTIC_CONTINUE` 仅是**建议**，不能认证权限。

# 02｜算法实现、单元验证与根因诊断

**加载条件**：有可验证研究问题，需要落地最小算法、改核心模块，或有 shape/梯度/数值/速度/集成异常。对应 `03-A/C/E`。优先复用项目当前代码、venv、测试与已有有效 Run；不重建环境、不一上来部署多 Agent。

## A. 从科研命题生成最小架构

输出一页以内的实现合同：
- **Input/Output**：shape、dtype、单位、时间索引/部署时已知信息、mask语义、target和评价接口。
- **Backbone**：采用成熟且已可运行的最小必要编码器；新机制是哪个具体函数/模块/训练规则？为什么常规模型没有此归纳偏置？
- **Loss**：逐项写公式、目标、优化方向、量纲/权重，尤其标明监督信号是否独立、是否使用测试时未知未来值。
- **对照不变量**：指定不改动的数据划分/评估器、固定输入信息/预算和需测试的负对照。
- **运行边界**：需改的文件、已有授权资源/时间/次数；没有真实用户授权不触发 GPU、付费、正式训练或远程发布。

不为“看起来创新”新增没有可验证预测的模块。优先使简单算法与强基线接入**同一个评价器**。假设模块无效时应能通过消融移除。

## B. 具体技术测试（按任务/故障选最少必要项）

| 类别 | 具体方法 | 能支持的结论 |
|---|---|---|
| 数据/形状 | 真实 batch 的 shape、dtype、NaN/Inf、mask/长度边界、超长短序列 | 接口符合本任务 |
| 时间因果 | 改变未来时刻输入后，当前预测不应变化；必要时检查在线状态缓存 | 未意外偷看未来 |
| 梯度 | forward/backward、参数梯度非 None 且有限、关键模块梯度有路径；检查冻结参数 | 数值路径可训练 |
| 损失 | 小型构造算例与已知结果对照；检查负样本/类别权重/正则系数 | loss 语义正确 |
| 学习能力 | 固定极小训练子集的受控过拟合（不含正式 test） | 发现数据管线/优化 Bug；**不等于泛化** |
| 复现 | 相同软件/随机种子下结果在合理容差内；记录 GPU 非确定性 | 工程复现边界 |
| 资源 | 先测实际 batch 的显存、吞吐、单实验时间及依赖链路；显存风险按可执行证据给出 | 后续预算估算，不等于论文效率贡献 |
| 结果完整性 | 确认日志、预测、配置、数据与 commit 指纹完整，并保留失败 run | 结果可追溯 |

**区别 TDD 与科研探索**：对已知确定行为（时间因果、shape、公式、不变量、修复的 Bug）采用 Superpowers 式 red→green→回归；对未知科学结果（新方法必须优于 baseline）不能先把想要的正结果写成必过的单元测试。正式科研贡献由独立实验验证而非测试用例保证。

## C. 出现异常时按根因而非“调到能跑”

1. **复现**：保留最小失败输入、堆栈、日志、原 Run/commit，界定是否所有条件都失败。
2. **定位**：比较最后一个可信版本与新变化；沿数据→模型→loss→优化→评价找第一个不一致点。
3. **竞争解释**：优先分开 `ENGINEERING`、`DATA/PROTOCOL`、`SCIENTIFIC_NO_GAIN`、`RESOURCE`；为最可能根因设计一个小而可证伪的诊断。
4. **最小修复**：单点变更，运行原失败用例与受影响回归；如果改了数学目标/数据切分/评估器，对旧 Run 逐条标 `INVALID` 或 `EXPLORATORY`，不能静默继承。
5. **价值检查**：复杂修复前问“成功后能改变哪个科研决定/有效性/论文主张？”不能改变且非安全/真实性必需就停止扩展修复。

## D. 本次任务的验收与交接

最少交付：改动文件与 Git diff/commit、一个可重复执行的相关测试命令及真实输出（不运行记 NOT_RUN）、必要真实 batch 的端到端证据、受影响 Run ID、一个下一科学问题。测试全绿也只能宣称 `ENGINEERING_VALID`；机制、真实任务与论文新颖性单独记录。

自修复已获授权的普通 Bug 与受影响测试可连续进行，不要求每次停下问；新增 GPU/付费、实验协议冻结/变更、新研究方向、外传与投稿属于独立用户门禁。

## E. 模块级实现合同与复杂度预算（P0-1）

正式写入新模块前，在现有 `TASK_CONTRACT` 或研发笔记中填**具体值**（不是再生成冗长计划）：

| 合同项 | Agent 必须提供的可检查内容 |
|---|---|
| 科学差额 | 最近邻现有方法在哪一个可观测条件失败；新机制预计改变哪项结果 |
| 输入/输出 | 张量 `[B,T,C]` 等明确形状、dtype、物理单位、mask、预测 horizon；推理时合法可得信息 |
| 模块与接口 | 拟修改文件、函数签名、返回类型、与现有 backbone/评价器的接入点 |
| 表征与机制 | 引入的状态、latent、gate、记忆或约束的实际含义；与简单替代的可证伪差异 |
| Loss/训练 | 每项 loss 的数学定义与方向、监督/负样本来源、权重、optimizer、冻结/可训练参数与更新顺序 |
| 推理契约 | 训练用标签/教师/未来信息在部署时如何消失；推理缓存初始化和更新时序 |
| 复杂度预算 | **复用**什么、**新增**什么、刻意**不采用**什么；多一个模块增加多少参数、推理/训练成本 |
| 移除证据 | 哪项消融/替代实验若无收益就删除模块；同样性能时优先简单实现 |

**一个核心贡献优先**。如果一项创新无法对应一个可独立检验的机制预测、也无法从 backbone 中单独移除，则优先简化而不是追加注意力、专家、记忆、额外 Loss 等装饰性模块。实际公式、API 和张量索引应由项目代码/数据核实，不凭空规定。

## F. 关键行为测试矩阵（P0-2，按改动影响选择）

测试的目标是证明*已知不变量*，而非写一个“模型必须超越基线”的伪单元测试。为每项核心改动列 `test_name | 构造/真实最小输入 | 期望不变量 | 实际命令及退出状态`：

| 改动触发 | 可执行测试思路 | 失败通常指向 |
|---|---|---|
| 时序/在线决策 | 固定当前及过去，独立改写未来帧/标签；当前输出不应变化。对不同 t/h 检查 `target_idx` 与 timestamp 对齐 | 非因果窗口、缓存、target 构造错误 |
| 模态/Mask | 全缺失、单模态、边界长度、填充位置变化；被 mask 的无效值不应改变合法结果 | mask 广播、默认填充值捷径 |
| 新 Loss | 手算两三个微型样例；检查权重=0、零正样本/空窗口、对称/单调性质（适用时） | 归约方向、标签、数值稳定性 |
| 梯度/可训练性 | 受控 batch forward/backward；有限 loss 与关键参数梯度；冻结参数无梯度；tiny-set 可过拟合 | 梯度断裂、优化器漏参数、标签噪声 |
| 推理/评估 | 禁用训练专用信息，随机改变无关顺序；确认相同 `sample_id`、预测/目标形状及评估掩码 | train/test 路径不一致、样本丢失 |
| 可复现性 | 固定 seed/数据版本重复关键 CPU smoke，必要时设置合理 GPU 数值容差 | 隐式状态、非确定性或环境漂移 |

优先补行为/回归测试；对已知 Bug 要求先复现失败→最小修复→原失败测试通过→受影响测试回归。较大任务可一次连续完成相关实现和测试，不要求每个函数新开审查。**tiny-set 过拟合只是可学习性检查，不是正式性能证据**。

## G. 从训练症状到最小定位实验（P0-5）

| 观察 | 首先核对 | 第一项判别动作 | 禁止误判 |
|---|---|---|---|
| Loss 不下降/NaN | 标签、输入尺度、梯度/优化器参数覆盖、loss 符号与 fp16/bf16 | 固定真实小 batch + 有限值/梯度 + tiny-set 学习曲线；必要时 fp32 对照 | 直接宣称主张无效，或无界调参 |
| 训练好/验证差 | 独立组划分、数据处理泄漏、样本/标签分布、容量与正则 | 按对象/episode 分组的误差分布；保持评估脚本不变 | 选择最好 seed 冒充泛化 |
| 效果输给 Ridge/Persistence | 同时域、同输入历史、归一化/目标定义、有效样本分母 | 在同一评价器按条件输出残差和配对误差 | 盲目加大 Transformer |
| 消融造成下降 | 参数量、输入信息、训练预算与门控成本 | 容量匹配替代、内容打乱/时间位移等能排除捷径的负对照 | 将消融下降等同因果机制证明 |
| GPU OOM/慢 | 真实 batch、激活显存、序列长度、编译/算子与 IO | CPU/小规模合法探测，区分 peak VRAM、数据加载和 kernel | 将一次前向通过当可完成整套实验 |
| 已有大量工程 PASS、价值不明 | 中心 Claim、最近邻、主任务真值与代理指标差异 | 最低成本真实价值判别；无路径则建议 HOLD/收窄 | 继续修外围工程问题 |

每次只保留 **最可能改变下一科研决定** 的 1–2 项检查。若发现 `DATA/PROTOCOL` 缺陷，受影响 Run 降级 `INVALID` 并追踪下游；`SCIENTIFIC_NO_GAIN` 保留为有效负结果。确认过程中的正式测试/新训练仍需原有真实授权。

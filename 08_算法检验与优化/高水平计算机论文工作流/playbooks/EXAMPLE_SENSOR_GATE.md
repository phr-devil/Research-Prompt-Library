# 操作实例｜视觉主导控制何时调用触觉传感器？

> **教学级映射，不是新数据审计或实验结果。** 仅演示如何把用户已确定的传感器科研课题转换成 WorkBuddy/Codex 的任务、对照和验收。真实数据是否有闭环动作、成功率或触觉开关记录，需要在本项目独立核对。

## 1. 问题及可证伪主张

研究问题：在控制视觉、机器人状态、过去动作信息与感知成本后，动态触觉查询策略能否比固定规则或随机门控**在相同传感器使用率下**提供额外任务信息或闭环控制收益？

- 时间 t 已知：过去与当前允许的视觉/机器人状态、历史触觉（若此前已开启）、传感器是否可用及其成本；**t 时刻尚未读取的触觉数据不得用于决定是否启动**。
- 输出：`gate[t] in {0,1}`，及预定义的任务输出（未来状态、事件、控制代价或闭环表现）；明确预测 horizon 与时钟。
- 需要验证的新知识：不是“融合准确率提高”，而是**条件化感知选择是否有效利用视觉无法辨别的接触状态，以及何种条件下值得调用触觉**。
- 替代解释：gate 只利用阶段标签、时间索引、机器人状态或数据缺失模式；改进来自更多观测/算力/参数量，而非决策机制。

## 2. 数据准入和决定可宣称的范围

可先检查已有 FMB 等包含力/扭矩、状态、动作及任务阶段的公开数据是否适合**离线任务**；必须核实每项字段时序、在线可用性、任务标签是否与门控目标独立。若只有离线阶段序列，没有真实的触觉按需采集记录或可执行闭环环境，就不能仅凭预测改善宣称节省实际采集成本或提高闭环成功率。

如确实需要闭环任务收益，必须先证实模拟器/真实环境具有 `reset→obs→gate触觉→action→step→metric` 的完整合法链路；仅加载预训练权重、模型 forward 或 CEM 输出不算闭环验证。缺链路时保留离线科学命题，外部收益标 `VALUE_UNVERIFIED`。

## 3. 实施层：一次综合研发任务

- **数据契约**：定义 t、可读触觉窗口、目标 t+h、group split 和物理单位/unknown；写时间因果与 train-only 处理测试。
- **基线**：Vision/State-only；Always-on（上限/成本对照，不在相同查询率的比较里强行当同预算）；固定间隔/随机门控（严格匹配触觉调用率）；合法可实现的现有门控方法；带 gate 的最小算法。
- **算法**：复用成熟视觉/状态编码器 + 小门控头；损失明确任务指标与触觉费用的权衡；检查是否训练时用了决策前未知触觉，是否有梯度捷径。
- **测试**：真实 batch、输入/输出 mask、t 后未来值篡改不能改变 gate[t]、小样本过拟合、在合法开发集比较成本—性能曲线。
- **机制证据**：冻结相同 gate 预算进行传感器内容打乱/历史触觉替换/阶段状态对照；容量相当的门控头消融。预定义哪个对照会区分“真实接触信息”与“阶段捷径”。
- **记录**：每个实验记录 commit、数据和协议版本、seed、episode/object 独立统计单位、原始预测、调用率、任务代理/真实任务指标、CPU/GPU实际耗时及结果状态。

## 4. 科学判断与失败处理

- **正结果**：若离线评价有稳健提升且负对照否定部分捷径，可支持限定的数据模态信息增量；只有合法闭环实验才支持控制收益。
- **无收益**：先核门控率、输入/任务公平、强基线和可辨识性；有效无收益不是工程 bug，也不是无需再审就 STOP。
- **负对照同样有效**：优先怀疑阶段/时间/动作信息捷径，不增加模型复杂度掩盖问题。
- **确认集泄漏**：使受影响的确认性结论 INVALID，不得换 seed 在同一 test 重新选模。
- **外部依赖 RED**：停闭环宣称与相关训练，保留离线数据/代码/可验证发现，向用户说明低成本替代或缩窄主张。

# 04｜机制证据、统计确认、论文主张映射

**加载条件**：已有可信探索结果、准备正式确认性宣称，或审稿前发现“指标提升却不能证明创新机制”。对应 `03-B/F` 与 `04-A/B/C/D`。独立审查只在重要主张上有信息价值时触发。

## A. 先写需要证明的主张，而不是先画最好看的图

典型 1–3 条：
- C1 **数据/任务贡献**：某种感知信息是否在部署可得条件下提供独立增量？
- C2 **机制贡献**：新模块的预定响应、反事实或失效边界是否与竞争解释有区别？
- C3 **任务/理论价值**：真实控制/任务、理论规律或跨域性质是否获得独立证据？

同一实验可能支持多条，但不能自动从 `ENGINEERING_VALID` 推出 `MECHANISM_SUPPORTED` 或 `TASK_OR_THEORY_VALUE_SUPPORTED`。如果只有离线模型代理或阶段标签，标题、摘要和论文 claim 必须限定在离线层次。

## B. 最小证据矩阵（复用 CLAIMS.md）

| Claim | 最可能反证 | 必需比较 | 证据与独立单位 | 可宣称级别 |
|---|---|---|---|---|
| 新增模态/信息有用 | 状态/动作/时间捷径 | 公平单模态、全模态、空模态/内容打乱（匹配结构） | 独立对象/episode、配对效应与CI | 相关增量；因果解释仍需干预设计 |
| 新机制起作用 | 容量或调参预算更大 | 功能消融、容量匹配/替代机制、负对照 | 机制预测、主指标与失败区域 | 机制支持/部分支持/未证 |
| 任务可受益 | 离线 proxy 与控制效果脱节 | 实际闭环任务或合法高保真替代、成本与限制 | 任务成功、违例、传感器费用/延迟 | 仅在真实任务证据充分时宣称任务收益 |
| 方法可泛化 | 对象/任务泄漏与挑子群 | 预定的 unseen object/domain/horizon | 独立 group、全 seed、分布变化与CI | 泛化条件与边界 |

实验可能因不可获取的独立真值而只支持缩窄主张，不能补一个“合成正控”宣称真实任务已证实。

## C. 正式确认协议（需要单独用户授权）

1. 明确开发阶段已尝试的实验/seed/确认数据接触历史，确定合法未参与模型选择的 test；若 test 已污染，不能仅重跑同一 test 就当新独立证据。
2. 冻结主要主张、主指标及方向、独立统计单位、数据分组、强基线、负对照、选择的最终模型、拟运行 seeds/次数、预算与排除规则；任何变更版本化并说明对旧宣称的影响。
3. 在真实用户许可的资源上执行确认性实验，保存原始预测、失败尝试、代码/数据/协议/评估指纹和统计脚本。样本为配对比较时使用配对分析；有组内相关时按 group 聚类，需有足够独立 group 才能做稳健推断。
4. 给出点估计、效应量、CI、n/统计单位、预先约定的实际有意义差异；多任务/多条件/多假设时明确探索性筛选与多重比较，而非用一个漂亮 p 值代表全部。
5. 独立审查者依据原始代码/Run/数据重算最易推翻的 1–3 条主张；同一开发会话自评不能叫 independent review。缺条件记 `NOT_REPRODUCED`。
6. 将结果登记 `SUPPORTED / PARTIAL / UNVERIFIED / REFUTED` 与原始证据路径。正式主张不支持时，删掉、收窄或写明限制，不以改图/修辞替代实验。

## D. 实际论文图表怎样构成论证

优先按逻辑排，不要求每一论文都凑齐同样的图：
- **图1 问题/机制与时间因果**：哪些输入在决策时可得，机制预计在哪些情况下优于既有方法。
- **图2 主任务/主指标**：新方法 vs 最简单、最接近、最强可行对照；同一 test 与有效独立单位。
- **图3 消融与竞争解释**：拆掉创新点、打乱非必要信息、控制模型参数量/预算，解释“为什么有效或无效”。
- **图4 泛化/鲁棒/成本与边界**：跨对象/域/时间尺度、计算与传感器调用成本、失败条件。
- **附录**：数据来源与许可、训练与评估细节、所有 seeds、模型与脚本指纹、统计方法、负结果。

每幅图的原始输入、脚本、生成版本及 Claim/Run 编号必须可追踪；避免手动重新抄数和未披露筛选。

## E. 论文竞争力判断（不虚构成功率）

仅在真实证据支持下评价：最近邻工作是否已经实现同一贡献、结果是否包含科学上有意义的差额、强基线及机制证据是否完整、能否支持既定目标期刊的主要审稿质疑。**有显著提升并不自动意味着具有高水平论文创新性。**

最后仅给一项建议：`WRITE_DRAFT`（明确未验证部分）/ `TARGETED_EVIDENCE`（最便宜关键补验）/ `PIVOT`（新主张需用户确认）/ `HOLD`。正式外传、投稿以及新冻结实验仍需用户单独批准。

## F. 可运行的证据预审与主张审计（P0-7）

当项目有可复算的数字结果时，推荐使用仓库自带、**零第三方 Python 依赖**的 [audit_evidence.py](../../../research_tools/audit_evidence.py) 与对应 [使用约定](../../../research_tools/README.md)。审计器不会训练、不修改实验数据、不向外网传输。 当关键主张要求完整代码/数据/协议身份时使用 `--require-identity`：已在 RUNS 填写但未由原始结构化指标来源记录的版本字段将使该数字的完整谱系检查为 UNVERIFIED。默认模式仅核数字来源、并显示未嵌入的身份字段。项目已有等价验证器时优先复用，不要求迁移。

审计在两个不同层次进行：

1. **机器可判定的来源检查**：Run ID 唯一；引用的文件在指定 project root 内且存在；声明的 metric/value 与机器可读取结果一致；Run 标为 INVALID 的引用不得作为有效 Claim；显式提供的 run/version/split/seed/protocol/config/unit 字段如与原始结果冲突则判失败；无法复算/缺失强制字段一律记 `UNVERIFIED` 而不是 PASS。
2. **科学支持检查**：即使原始数字确实存在，也必须独立检查该数字的计算口径、独立统计单位、比较是否公平、因果/机制替代解释及论文可宣称边界。机器 `SOURCE_MATCH` **不等于** `SCIENTIFICALLY_SUPPORTED`。

用户未要求或项目没有数字来源时不生成空的“PASS”报告；原始证据不齐则报告缺口。报告应指向旧 Run 与 Claim，不复制整套新证据台账。可选 `claims_audit.json` 仅列需要核对的数值主张，作为 `CLAIMS.md` 的机器可读辅助索引，不替代主张表。

## G. 封闭确认评价与污染处理（P0-8）

- **开发阶段**：仅用训练与开发/验证材料选择网络、阈值、特征、预处理和超参；所有探索性比较保留在 Run 历史。
- **冻结时**：记录最后选定模型与配置指纹、数据分组与指标代码 hash、独立单位、预先指定主指标和统计方案、拟执行 seed/排除规则；冻结协议变更需独立用户授权。
- **确认阶段**：在获批范围内只使用预定义的未参与选择的 holdout 或可验证独立外部数据；保留评估访问记录，结果写入与探索分开的 Run/目录；不允许根据确认结果再次挑模型、改主指标或再次调参。
- **污染处理**：一旦确认集被用于选择方案或反复优化，相关结果只能标为探索性；若无新独立数据，则明确 `CONFIRMATION_UNAVAILABLE`，不得将原 test 改名后自称“全新确认”。
- **事后分析**：失败区域/子群/误差机制可探索并注明 post-hoc，下一次真正确认须新合法数据与新协议，不把 post-hoc 最佳子群当先验主张。

这是从 [AI-Scientist-v3](https://github.com/SakanaAI/AI-Scientist-v3) 借鉴封闭最终评价的原则，不要求安装其容器、评估系统或第三方 Agent。**正式实验/GPU/论文外传依旧保留真实用户授权门禁**。

# 01｜数据、评价器与强基线：先证明比较合法

**何时读**：新数据、基线不可复现、指标/标签/划分变更、传感器时间对齐不明。先复用项目可信 Run，不要求重新采集/训练。关联 `02-B`、`03-B`。

## 1. 先锁定真实可检验任务

Agent 从真实数据和部署条件写 6 项**具体值**，不填泛泛原则：

`Claim | Input(t)与部署可见信息 | Target(t+h)/独立真值来源 | group与时钟/单位 | split与预处理拟合范围 | primary metric及分母`

- 查看字段、许可证、对象/episode ID、时间戳、频率/异步偏差、缺失、标签生成代码。**模型生成/同源派生标签 ≠ 独立真值**；无真实闭环记录不能把离线预测称为控制精度/成功率。
- 按科学泛化目标选独立分组（对象、任务、受试者、会话等），使 train/val/holdout 不交叉；需要时间预测时确保输入仅为 t 前可见值、目标时间严格按任务定义。标准化/阈值/特征筛选仅 fit train；验证/测试不参与拟合。
- 先用一个真实小 batch 检查 shape、dtype、单位、NaN、时间对齐、正负标签、ID 唯一性；对一组手算样例重算评价指标，保存评价器指纹。

### 主张—数据双向核验（选题后的真实证据层）

沿用F4已核的只读证据，按`Claim → required observable → independent truth/proxy → legal group split/time causality → primary metric → unavailable counterfactual`用真实字段复核；并从数据反推“究竟能严谨回答什么问题”。标`TRUTH_CONFIRMED / PROXY_ONLY / UNKNOWN / UNAVAILABLE`。若缺闭环因果可识别性，只能验证离线代理任务，不得宣称改变传感器启用策略后提高控制成功率。

## 2. 强基线复现合同（P0-3）

**最低两档**：常量/多数类、Persistence、Ridge/AR 等最简单可信方法（按任务选）＋真正最接近的可运行强基线；必要时加标准 backbone。不要因为论文用了“更先进”的模型就认为是强基线。

| 对齐维度 | 必须相同或写明不能比较的原因 |
|---|---|
| **任务** | target、horizon（真实时间还是帧数）、时序容差、正负定义 |
| **信息** | 输入模态、历史窗口、动作/未来信息、可用触觉次数/成本；Oracle 必须注明特权信息/可行策略集；未证明最优时仅作诊断参考 |
| **评价** | 相同 sample/group IDs、有效掩码、排除规则、metric 代码和分母 |
| **训练公平** | 可比数据、合理且透明的调参机会/训练资源；不能暗中不给基线调学习率 |
| **可复算** | 官方方法/版本或已验证 Run、数据/配置/协议指纹、预测或指标来源 |

按 `官方/既有证据 → 本地重算评价 → 一项差异诊断` 递进；原作者数据/权重/协议不同的论文分数仅作参考。强方法复现失败记 `STRONG_BASELINE_NOT_REPRODUCED`，附最可能差异与低成本替代，不用失败的弱实现宣称 SOTA。

**最小测试**（按真实字段实现，不把示例当现成测试）：train/val/test 分组无交集；只改未来时刻输入不得改变当前预测（适用在线模型时）；train-only 拟合；新法与对照按相同 `sample_id,group_id,target,prediction,valid_mask` 对齐；全部失败样本也计入覆盖率报告。时序/标签或 metric 代码改变时，标注哪些旧 Run 不再可比，只重算受影响下游（可参照 [DVC](https://github.com/treeverse/dvc)）。

## 2.5 性能空间诊断（不增加实验门禁）

先复用现有 Run，在**同一开发协议**估计：`B_simple | B_strong | O_reference（可选） | gap与不确定性 | 错误集中条件 | 下一判别实验`。所有指标写方向、合法独立单位、覆盖率及置信度。无可行 Oracle 就标 `O_UNKNOWN`，不制造数值。

- **B_strong** 是公平调参的可信强基线。对比差额与实际有意义的效应阈值，按对象/接触阶段/时域/失效条件做预先有理由的分组残差；探索性子群需标记，不能在相同验证集挑最好者冒充确认结果。
- **O_reference** 可取含特权信息的参考策略、受限假设类中的最优解或离线估计，但必须逐一标注信息、可行策略集合、目标与最优性证据。**没有最优性证明的 Oracle 不是数学上界**；若任务/成本口径不同，不计算 `O−B`，只能并列诊断。
- **动态传感器/控制**：离线遮蔽、Oracle 或只观察被记录动作的数据，通常不能直接识别未执行策略的闭环因果收益；没有覆盖性/可识别性假设与证据时，结果只限离线预测/代理分析。
- **分叉**：差额集中且有可实现机制 → 进入少量竞争机制；强基线接近可靠上界 → 收窄价值或 HOLD；无独立真值/参考不可信 → `VALUE_UNVERIFIED` 或 `INCONCLUSIVE`，优先补数据/评价，不扩模。

### 动态门控的可利用性能空间（相关时按需，不增加必过门禁）

同时区分`B_strong`（公平强基线）、`O_reference`（说明特权未来/标签的诊断参考）及`P_feasible`（仅部署决策前可见信息下的轻量经验策略，例如固定规则/线性选择器；必要时CPU小试）。`O_reference`无最优性证明不是数学上界，不能假定差额可达；`P_feasible`表现差也不是复杂方法不可行的证明。缺数据或授权标`P_UNKNOWN`而不编造数值。三者的任务、时序、信息、成本和独立统计单位须能对齐；代理改善须有与真实任务区分的低成本反证。

## 3. 判断与交付

- `READY`：真实数据、独立性/因果、指标与至少一个可信简单基线可复核；相应 Pilot 仍需实际资源授权。
- `LIMITED/VALUE_UNVERIFIED`：只有代理标签/离线指标；可继续合法探索，但收窄科学主张。
- `INVALID/BLOCKED`：标签循环、不可修复泄漏、关键真值或闭环缺失；只阻断受影响主张/实验。外部数据缺失时记 `WAITING_FOR_DATA`，不以合成数据填补真实性。

**只交付**：6 项任务合同＋1 张真实基线对比/阻断表＋原始证据指针，不新建重复台账。

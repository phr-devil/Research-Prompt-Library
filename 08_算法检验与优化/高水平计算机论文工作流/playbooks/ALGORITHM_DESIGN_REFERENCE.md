# 算法架构选择与创新机制参考（按需读取，不是新审批阶段）

**何时读**：拟生成机制、选backbone/模块或复杂模型未超简单基线；先复用真实Run、近邻与指标，只保留有依据的少量候选，不遍历架构。

## A. 先判断问题，再选归纳偏置

| 可观察问题与条件 | 优先比较 | 关键反证与代价 |
|---|---|---|
| 连续量短期预测、样本少、强自相关 | Persistence / Ridge-AR / Residual-Ridge / 轻量 TCN | 若线性残差已解释主误差，复杂模型的额外信息来自哪里？ |
| 时序局部事件、实时、有限算力 | TCN / GRU / 显式事件状态 | 事件边界可否直接由时间/阈值预测？有限缓存是否足够？ |
| 长程依赖、上下文可变 | GRU / TCN / Transformer / SSM（若原环境已有） | 长记忆确有必要吗？更长输入是否带来公平收益和内存成本？ |
| 异步视觉、触觉、力觉融合 | 单模态、早/晚融合、跨模态融合 | 同时间点对齐是否合法？收益是否来自动作/阶段捷径或多参数？ |
| 按需启动传感器/预算约束 | 固定间隔、规则/阈值、学习门控 | 决策前可见哪些信息？相同传感器成本下是否更好？ |
| 具有已知物理过程、漂移/校准 | 物理/滤波基线、残差学习、结构化状态 | 新模型究竟改善何种物理条件下的残差？ |

**机制机会判断（复用01手册）**：从配对残差的稳定失效条件或具名论文/物理先验生成机制；先核合法推理信息、成本、同输入简单替代与独立统计单位。新机制和替代各有可分辨结果签名；动态门控缺可识别信号只否定受影响门控，不否定其他归纳偏置。Oracle≠可达增益；无Run记HYPOTHESIZED/UNKNOWN，不虚构效果。

**选择原则**：保留可复算简单基线与最小创新机制；仅有科学依据才扩模。不能凭模型名或参数量推断收益；比较要对齐输入、数据、调参和任务。

## B. 设计新机制前必须填写的五问

1. **差额**：最近邻论文/当前最强有效 Run 已实现什么，在哪一类**可观测条件**不足？
2. **机制**：新表示/状态/门控具体计算什么，输入→中间表示→输出的张量、时序和 Loss 公式是什么？
3. **替代**：相同可用信息下，线性、MLP、容量匹配普通模块或固定/随机门控哪一个最能挑战创新？
4. **签名**：若新机制为真，在哪个干预/切片下与替代解释预期不同？例如按任务阶段匹配后打乱力觉内容是否还保留增益。
5. **成本与删除**：新增参数、峰值内存、每样本延迟/传感器启用成本预期多少？哪个合法对照失败就删模块？

**最小产物**（可直接写入现有 TASK_CONTRACT；机制选择不是论文新颖性证明）：

`Claim | candidate A(simple), B(new), C(optional near-neighbor) | expected signature | method API & loss | information/cost controls | decisive ablation | removal condition`

低功效/短时负Pilot不能否定整个机制族；若真值或评价不足先返回[01 数据](01_DATA_BASELINE.md)，否则不要无限换架构。

## B.5 有限机制竞争（仅当真实数据与对照具备）

从配对残差或可核理论来源选择最有信息价值的失效条件；按证据生成少量**原理不同**的机制，非固定凑三。保留三个实验角色（可以只有两个）：
- `M0`：最简单可信、信息与成本匹配的对照；
- `M1`：机制假说 A 的最小实现；
- `M2`（可选）：归纳偏置真正不同、能解释相同失败场景的假说 B。

**机制生成配方**：从`条件误差/可核先验→可能缺的信息或偏置→与最强替代不同的预测`提出候选，按机制归因选判别合同：
- **额外信息**：核该信息的合法可得性与条件增量；未观察动作的反事实收益不可直接估算。
- **归纳偏置**：同输入与公平容量下，在依赖距离/异步/物理扰动等预期条件做压力测试。
- **优化机制**：固定架构、数据及合理初始化分布，比较训练轨迹、稳定性与同预算结果。
- **容量机制**：匹配参数/计算/调参机会，比较普通模块是否能解释差额。
失败转向只在原Run/具名证据指向另一个可辨别原因时生成邻近机制；无原始Run的新设想仍可标`HYPOTHESIZED`，不强制生成候选数量或立即训练。

写 `机制 | 预期成功条件 | A/B 会产生不同结果的负对照 | 需要的合法真值 | 计算/传感成本 | 删除条件`。比如动态触觉门控中，不确定性驱动与事件变化驱动的模型应在**决策前可见信息相同**的条件下比较；打乱触觉内容只可用于已获触觉后的信息增益检验，不能让启用前的模型窥见未来触觉。

先用判别力/成本挑实验，而非仅找最容易否定的项。若容量、阶段提示或调参可解释收益则收窄Claim；有效无增益后按失败原因生成另一归纳偏置候选，而非反复叠模块。见[数据](01_DATA_BASELINE.md)、[实验](03_EXPERIMENT_LOOP.md)。

## C. 实现前的硬问题（可直接交给 WorkBuddy）

- **数学**：shape、时间、mask、单位、Loss来源；禁在推理中使用teacher/未来观测。
- **系统**：可模块化接入、保存加载、缓存与合法CPU/GPU算子及真实数据兼容。
- **公平**：合理调优*nuisance*，固定target/样本/部署信息/评价器，报告算力延迟。
- **审查**：先按 [02 实现与调试](02_BUILD_DEBUG.md) 运行行为与参考实现对照；机制效果再交 [03 实验迭代](03_EXPERIMENT_LOOP.md)，不能让单元测试伪造科学收益。

# 03｜有界科学实验迭代与失败诊断（可交给 WorkBuddy/Codex）

**加载条件**：真实数据与可比基线已具备，下一目标是改进算法、解释无增益或分析机制。对应 `02-C/E`、`03-D/E`。借鉴 Autoresearch 的固定评价与实验账本、AI-Scientist 的竞争假设与有界分支探索；**不执行 LOOP FOREVER**。

## A. 每次探索只定义“可能改变决定”的科学问题

用以下 8 个字段写一个极短实验合同，而不是重新规划整个项目：

`claim_id | 当前最佳有效Run | 竞争解释A/B | 改动的一个机制 | 新证据将怎样区分A/B | 固定开发评价+强基线 | 预算/授权 | KEEP/DISCARD/INCONCLUSIVE/INVALID判据`

示例：视觉+触觉优于视觉单模态，可能是力觉真正提供了视觉缺失的接触信息（A），也可能是来自可见机器人动作/任务阶段的捷径（B）。在**控制相同信息和门控成本**后打乱触觉内容，A/B预期不同；只有原本方法比随机门控好不能排除B。

**先设最小科学对照**，再决定是否修改网络。典型竞争解释：标签/划分泄漏、时间窗口不一致、任务阶段捷径、模型容量差、可用信息不公平、样本聚类、随机种子方差、当前机制无效。对于科研发现类项目，真实负结果与稳健失效边界也可能是有效产出。

## B. 运行前，冻结本轮可比较的开发条件

- 将独立真值/样本单位、train/val/开发集、目标时间 horizon、指标、预处理、数据版本、评估脚本、强基线版本和最大尝试预算绑定到 run；尚未正式冻结前可以为开发修改，但必须版本化并重算受影响对照。
- 对每个探索分支仅改一个可解释因素；架构复杂耦合时可成组修改，但不能将联合结果解释为单模块因果增益。
- 先复用最近可信 checkpoint 与代码；不要因为切换阶段而重复训练、下载或重跑原来有效结果。
- 对单卡实验，先通过**实际小规模测量**估算显存/时间，再选择批次、精度、序列长度；不凭模型参数量推断一定能在4080运行。
- 明确实际获批的 `max_gpu_time/max_wall_time/max_trials` 与停止条件；空值不代表有预算。单次中断重启只恢复未完成且获批的片段。

## C. 一次有界实验循环

1. **对照**：先确认当前 strongest valid baseline、主指标与全体样本覆盖，复用有效 Run。
2. **设想**：写“如果机制 X 成立，则在条件 C 下方法 A 的指标/响应应该怎样变化；若替代解释 Y 成立则怎样变化”。
3. **选择**：比较候选实验的信息价值、成本、能否获得独立真值；只选一项或几项共享设置、可以在同一授权里连续完成的实验。允许早期并列探索少量互异机制，但不要指数级分支树。
4. **实施**：在已获批范围运行；保留全部 seed/失败、原始预测、主指标、训练日志、配置/commit/数据身份；不可随手删不理想条件。
5. **核验**：核指标实现、独立统计单位、效应量和不确定性；对同一数据配对比较，bootstrap 按独立 group 聚类；当样本量小或大量候选被试过，明确置信度降低与选择偏差。
6. **决策**：`KEEP` = 评价合法、在预定开发目标上确有增量且复杂度值得；`DISCARD` = 有效比较但不优/机制不被支持；`INCONCLUSIVE` = 信息不足不能区分；`INVALID` = 评价、代码、泄漏或权限影响证据。二者不是一回事。
7. **下一项**：只当新的实验能区分剩余竞争解释、影响科学主张或恢复不可缺失的有效性时继续。否则建议 HOLD/PIVOT/收窄主张；重大方向/权限变化交用户决定。

**简单性优先**：效果相同优先更简洁、可解释、可复现的方案。不要为极小、未稳健的提升引入大量复杂模块。

## D. 根据症状优先做什么（不是无限调参菜单）

| 观察 | 首先核查/实验 | 不应立即做 |
|---|---|---|
| 新模型输给 Persistence / Ridge / 标准 Backbone | 目标、horizon、分组、归一化、强基线公平与误差条件分布 | 盲目扩大网络与重训所有基线 |
| 训练 loss 好但开发指标差 | 数据切分、同一对象近邻窗口、正负样本、过拟合与校准 | 最佳 seed 直接称为贡献 |
| 某个消融显著降低性能 | 控制参数量/训练信息/门控成本；补模态内容打乱或替代模块 | 将下降直接解释为新机制因果成立 |
| 代理指标涨而任务指标不涨 | 明确任务收益可否观测；一次最低成本的任务/独立机制证据 | 继续刷代理指标 |
| 某个域/跨度负增益 | 按预定义对象/任务分析；检查失效区间稳定性与样本数 | 只挑成功子群写正文 |
| 很多轮工程 PASS 但没有科学信息增量 | 反推主张及最近邻，问下一实验是否改变科研决定 | 无限修复、自动扩大预算 |

## E. 决策与日志模板（复用现有 RUNS.tsv/STATE）

```text
EXPERIMENT: C1 / R-017
HYPOTHESIS: A vs B -> 可区分的结果模式
CHANGE: 核心机制X；其余同版本R-014
COMPARISON: 简单/强基线，统一 split/horizon/metric
MEASURE: 主指标+真实任务/机制证据+成本；n与统计单位
EVIDENCE: 原始预测/脚本/commit/config/data split指纹
STATUS: KEEP|DISCARD|INCONCLUSIVE|INVALID
NEXT: 一项新判别实验 / HOLD / 用户重大决策
```

**严禁**：用正式 test 选模型或决定继续调参；把多个开发 seed 当独立重复观测；因结果不显著就声称证明了无效；隐瞒无增益与失败条件。正式确认实验转 [04 手册](04_EVIDENCE_CONFIRM.md)。

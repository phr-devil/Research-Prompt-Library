# 第八项 v5.2｜按缺陷严重度的修复与继续

> 只在**真实异常/验证未通过/结果与证据冲突**时按需调用。本文件和 [REPAIR_ROUTES.json](REPAIR_ROUTES.json) 与原有24条科研 Prompt 并行；不增设一整套必须执行的阶段，不要求每轮读完所有故障。避免“修不完的工程准备”。

## 核心：不要把每次失败都解释成“模型还不够大”

参考 [Superpowers systematic-debugging](https://github.com/obra/superpowers/blob/main/skills/systematic-debugging/SKILL.md) 的先复现再找根因、[test-driven-development](https://github.com/obra/superpowers/blob/main/skills/test-driven-development/SKILL.md) 的最小失败测试、[verification-before-completion](https://github.com/obra/superpowers/blob/main/skills/verification-before-completion/SKILL.md) 的修复后验证；[Karpathy autoresearch](https://github.com/karpathy/autoresearch/blob/master/program.md) 的固定预算/保留负结果；[Cleanlab](https://github.com/cleanlab/cleanlab) 数据标签问题检测；[MLflow](https://github.com/mlflow/mlflow) 的 Run 可追溯性；[Evidently](https://github.com/evidentlyai/evidently) 的数据与模型质量测试。**这些是设计参考，不是已安装或已执行的工具**，也不是科研效果背书。

先按 [TRIAGE.md](TRIAGE.md) 判断本次受影响目标：CRITICAL 禁止受影响的下一步；REPAIRABLE 由用户选择带限制继续/先修/调整；MINOR 自动记录跳过。科研负结果可以继续修改假设，而不是强行追求每层审核PASS。

## 发生失败时的单次修复循环

1. **CLASSIFY（辨型）**：先将失败分为 `ENGINEERING` 实现/设备、`DATA/LEAKAGE/PROTOCOL` 无效证据、`SCIENTIFIC/BASELINE/EVIDENCE` 科学前提与增益、`REVIEW/WRITING` 证据审核与论文、`AUTH` 权限。结果正常但仅不如预期，**不自动当 BUG**。
2. **LOCATE（最小证据）**：读取原失败日志、Run/Claim、commit、数据/分组/标签指纹、最后有效结果与修复历史；用 `workflow_route.py --repair 03-D` 只取当前 route 的常见问题。保留原有正常结果，不全仓扫描、不反复跑 GPU。
3. **HYPOTHESIS（一个具体根因）**：给一句“因为 X，导致 Y；可用 Z 最小检验证伪”，先验证问题是数据、代码、评价还是科学假设；无法定根因标 UNKNOWN，不靠猜测先改 5 个变量。
4. **VALUE_CHECK（修复科研价值）**：重要修复前先说明修好后将改变哪项实验有效性、主张或GO/STOP判断；若正反结果都不影响决定，跳过该修复。普通已授权Bug不额外审批。
5. **MIN_FIX（单点干预）**：工程问题先复现失败，改最少范围，运行针对性回归测试；数据泄漏或确认性 test 污染时**先冻结/标 INVALID**，只在合法未污染数据上重新评估；科学无增益先比较简单强基线、消融及不确定性，不通过随意换种子或反复 test 调参“修”出正结果。
6. **VERIFY（闭环）**：同一失败测试应转绿，受影响的回归/统计/科学主张需更新；保留负结果、证据 ID、耗时和当前预算。**工程问题修好了也不代表科学假设成立**，任何 `PASS` 必须按原 route 的验收条件判定。
7. **ESCALATE（按作用范围停止）**：许可/必要真值不可得、确认性test污染或未授权资源，对相应实验/正式声明标 BLOCKED_CRITICAL，但其余合法工作可继续。科学无增益但仍有可测试修改空间时为REPAIRABLE，交用户有界继续、修复、缩窄或HOLD的选择。普通工程故障若**连续3次尝试仍无法定位并修复**，先审查架构；同一科学假说建议最多两轮有明确区分力的定向诊断（默认建议值，不能覆盖项目已批准的更低预算），到达界限就报告未决，**不无限调参**。

### 修复类型差异

| 情况 | 最初应查的证据 | 可以采取的修复 | 禁止的做法 |
|---|---|---|---|
| 代码/环境异常 | 最小堆栈、形状、梯度、最近diff、环境版本 | 失败回归测试→单点修复→影响范围复验 | 一次改很多模块、只看无报错就宣布科学成功 |
| 数据、独立标签、泄漏 | 原始字段、采集来源、group split、归一化拟合范围 | 修划分或缩窄为代理任务，旧指标作废 | 编造独立真值、继续用被污染 test |
| 模型不收敛、NaN、OOM | loss/梯度/小样本过拟合、实际资源 | 在授权内做小规模定位和单因素实验 | 无限新模型、不断提高 GPU 预算 |
| 基线更强、增益消失 | 同任务、同 horizon、同分组、全seed与CI | 修正不公平对照；诊断机制是否真有新增信息 | 仅保留最好 seed、反复查看确认性 test |
| 独立审核复现失败 | Run/commit/data/评估脚本和版本 | 定向复核受影响项；证据不足则降级结论 | 自己复述冒充独立复核、重复全项目大审查 |
| 论文/图/返修不一致 | 原始结果、图脚本、Claim 和引用 | 修改可追溯文字和图，不足则请求补证据 | 编造实验、AI 未授权提交稿件 |

## 对现有 24 条 Prompt：失败后往哪里回？

下面是每条路由最常见的**第一排查方向**。每条路由另有两种常见异常的诊断与回退位置，存于 [REPAIR_ROUTES.json](REPAIR_ROUTES.json)；按需加载，不全文扫描。

| 阶段 | 验证步骤 | 典型失败和最小修复 |
|---|---|---|
| 01 | `01-A` | 问题过宽或无法证伪 → 缩为一个主假设+反证条件；近邻文献无法核实 → 核查关键论文原文并标UNKNOWN |
| 01 | `01-B` | 发现相同论文/模块 → 区分合理重合与真正新增贡献；强基线被遗漏 → 补同条件简单和最强对照 |
| 01 | `01-C` | 模块没有可证明作用 → 给出可检验机制和消融或删除模块；独立反证不可用 → 标记未独立复核并生成任务书 |
| 01 | `01-D` | 部分重合被误判无创新 → 回到贡献对照，不强制换题；所需真值不可获得 → 收窄主张或提交用户决策 |
| 02 | `02-A` | Pilot不能排除竞争解释 → 加入最小负对照与可否定判据；Pilot预算不足或未批准 → 只做低成本准备并申请明确预算 |
| 02 | `02-B` | 标签与输入同源/代理真值 → 追溯标签独立性，必要时收窄任务；同人跨拆分/未来信息 → 修复group split和train-only处理 |
| 02 | `02-C` | shape错误/代码异常 → 最小复现和固定测试，修一次根因；模型虚假优于弱基线 → 匹配horizon/输入/资源并重新对照 |
| 02 | `02-D` | 单seed正结果被宣布GO → 核统计单位、CI、探索与确认区别；模型并无稳定增益 → 一次有界诊断或HOLD，保留负结果 |
| 02 | `02-E` | 错误修复反复失败 → 回溯diff/根因并重新设计回归测试；持续换种子仍无收益 → 停止重复尝试，回决策门禁 |
| 03 | `03-A` | 跨阶段旧授权被继承 → 明确实验种类、GPU上限与新批准；实现合同与论文主张脱节 → 重写可验收输入输出和消融 |
| 03 | `03-B` | 冻结后修改切分或指标 → 作废受影响结果，需批准新协议；test被反复用于调参 → 停止确认性宣称，另行独立评估 |
| 03 | `03-C` | 单元测试/梯度实现错误 → 最小失败样例+一次根因修复；模型不学习/latent collapse → 核尺度/梯度并测试小样本过拟合 |
| 03 | `03-D` | NaN/OOM/训练震荡 → 小batch诊断后单因素调参；搜索多次只挑最好seed/无稳健增益 → 全seed统计，无收益则转03-E |
| 03 | `03-E` | 多轮调试仍无新增科学效应 → 回退到任务/数据/机制假设；连续修复引入新问题 → 停止盲修，检查架构耦合 |
| 03 | `03-F` | 确认集被用于挑模型 → 标记污染，不可调同一test；确认性结果推翻探索收益 → 如实报告并降级主张或请求新设计 |
| 04 | `04-A` | 复核方无法找到原始证据 → 形成Claim/Run/commit的最小审查任务书；审查范围过大 → 优先1–3项核心可推翻主张 |
| 04 | `04-B` | 开发者自评代替独立复核 → 标记未独立审核，找真实审查者；重算与原结果不一致 → 核数据指纹/seed/评价口径 |
| 04 | `04-C` | 补救造成更多回归 → 依影响图仅重测受影响Claim/Run；测试集污染无法消除 → 明确无确认性结论或申请新数据 |
| 04 | `04-D` | 论文主张超过真实贡献 → 降级为证据支持的贡献与范围；指标不理想直接判PIVOT → 先评剩余可证伪增量，交用户选择 |
| 05 | `05-A` | 叙事脱离已验证主张 → 映射每项贡献到Run/Claim；期刊/最近论文来源过时 → 增量核对官方资料 |
| 05 | `05-B` | 方法正文与训练日志不同 → 按真实超参/数据/seed改写；缺证据还写成正结果 → 删无证据句，申请定向验证或降级 |
| 05 | `05-C` | 图与原始统计对不上 → 统一脚本和输入版本并复算；只展示最好seed/遗漏失败 → 报告全seed、CI及失效样本 |
| 05 | `05-D` | 模拟审稿循环没完没了 → 仅修影响结论的Critical/Major问题；未获作者批准要投稿 → 停止外传与正式提交 |
| 05 | `05-E` | 回复声称完成不存在的实验 → 按实际Run证据修改回复；审稿新增GPU/付费任务 → 单列有限预算请求批准 |

## 限制与决策交互

- **默认不多问**：普通可确认的工程问题，仍在原任务范围和已授权预算内时直接纠错；科学证据或权限门禁才展示选择。菜单通常不超过3个选项，约4–8行；详细证据放科研项目原有 `research/STATE.md` / `RUNS.tsv` / `CLAIMS.md` / `REVIEW.md`，不要求新开日志系统。
- **记录最少量**：`INCIDENT: route / symptom / evidence / hypothesis / fix_attempt / verify / invalidated_claims / remaining_budget / next_route / needs_auth`。先写受影响范围和恢复入口，不覆盖旧版本，不把诊断结果写成新的科学真值。
- **可恢复**：有可信完成证据的 route 不因一个关联错误而全量重做；只重算被污染/改变的 Run 和 Claim，独立确认 test 不可因重跑而当作新测试集。
- **审批隔离**：`NEEDS_USER_DECISION`、`WAITING_FOR_USER_DECISION`、`BLOCKED` 均不授予 GPU/付费/冻结改动/投稿权限。独立第09章的“三候选 → 真实用户选定 → 05-R”门禁不变。

## 修复报告（给用户的短版）

~~~text
【当前】03-D：训练不稳定；不确定是梯度还是数据尺度。
【证据】Run-17 / loss NaN；原正常 Run-12 未改变。
【行动】已做获准的静态核查；建议先用一项小batch判别检查。
A｜继续许可内的 CPU 定位
B｜审核一项具体、限定预算的实验（另需明确资源批准）
C｜HOLD：保存结果并重审科学假设
~~~

若不需要人决策，不应为了显示菜单而强行中断。

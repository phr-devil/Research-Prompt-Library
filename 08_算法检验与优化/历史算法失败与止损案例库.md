## A. 如何理解状态和证据

| 状态 | 实际含义 |
|---|---|
| `MECHANISM_DISCARD / STOP_SCOPED` | 当前特定机制、Run或方向有真实负证据或已决定止损；**不等于研究领域已证伪** |
| `HOLD / RESOURCE_BLOCKED` | 项目投入价值、关键平台或真值尚不满足；不能冒充模型实验失败 |
| `CANDIDATE_FILTERED` | 选题或近邻审查时降级，**未必运行过算法** |
| `KEEP_SUBCLAIM / UNVERIFIED` | 有局部正证据，或者尚无可核实最终实验；**不要计入失败数量** |
| `RUN_RECHECK` | 本库仅有历史讨论/报告线索；采用数值或做新决策前必须核原始Run、协议、数据身份和独立统计单位 |

任何历史`PASS/FAIL`至少区分**工程、数据有效性、科学机制、真实任务、论文贡献**五种含义。负结论须记录`DECISION_SCOPE=RUN/MECHANISM/CLAIM/PROJECT`；未经验证记`UNKNOWN`，不可编造Git SHA或已获授权。

## G. 以后如何使用：仅嵌入既有第08章步骤

1. **ChatGPT选题 F1–F4**：先按候选风险匹配1–2条案例，做具名查新、真值/关键平台核查，写明`CORRECTABLE/PREDICTABLE/DISTINCT`哪些是已知、哪些要实验；不要求提前训练。见 [IDEA_FUNNEL](高水平计算机论文工作流/IDEA_FUNNEL.md)。
2. **第09章的已选失败项目转向**：区分可复用资产与被否定前提，Step05人工选择不变，05-R仅增量核实；不暗换已选题。见 [第09章](../09_失败算法项目挽救与转向/WORKFLOW.md)。
3. **WorkBuddy最小实验**：有合法授权后，优先`真实缺口→已知正控→决策前预测→简单强基线→独立论文价值`中最能改变当前决定的一项；**不增加5个强制关卡**。见 [POST_SELECTION](高水平计算机论文工作流/POST_SELECTION.md)。
4. **每轮结论**：仅对有效证据范围标`KEEP/DISCARD/INCONCLUSIVE/INVALID`和`RUN/MECHANISM/CLAIM/PROJECT`；真正缺新信息时HOLD，不因为任务能继续修就持续修。
5. **资源边界**：课题选择不等于CPU/GPU训练、正式确认、付费或投稿授权。用户禁训时，CPU Ridge拟合也不得进行。

## H. 更新与去重原则

- 新结果应附`project_identity / claim_id / run_id / commit / data&protocol_id / baseline / metric / independent_n / result_scope`；未知填`UNKNOWN`，不要杜撰ID。
- 最新、同一版本的**原始Run**优先于旧聊天摘要；若原结果后来被修正，更新本表并保留变更依据。
- **单一项目多个机制可以分别止损，但不能算独立项目失败次数**；同名P1/任务序号不具有跨聊天唯一性。
- 若开发数据/原test已经用于方法选择，不能重命名成`untouched holdout`。
- 本文用于避免重复错误，**不是反向禁止创新**，更不是对投稿成功概率的统计估算。保持小规模有判别力的探索与真实授权门禁。

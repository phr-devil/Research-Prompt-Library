## A. 如何理解状态和证据

**历史证据回连规则（按需、非新门禁）**：只有影响当前候选的案例才补`项目仓库URL/commit | 原始Run或日志路径 | 数据与协议身份 | 当时可见日期 | 适用Claim/DECISION_SCOPE`；无原始访问证据写`RUN_RECHECK/UNKNOWN`，不能把本表阶段摘要当作复现或时间点预测。原始材料存回对应科研项目，提示词库只保留可核指针，不复制完整日志/数据以节省Token。


| 状态 | 实际含义 |
|---|---|
| `MECHANISM_DISCARD / STOP_SCOPED` | 当前特定机制、Run或方向有真实负证据或已决定止损；**不等于研究领域已证伪** |
| `HOLD / RESOURCE_BLOCKED` | 项目投入价值、关键平台或真值尚不满足；不能冒充模型实验失败 |
| `CANDIDATE_FILTERED` | 选题或近邻审查时降级，**未必运行过算法** |
| `KEEP_SUBCLAIM / UNVERIFIED` | 有局部正证据，或者尚无可核实最终实验；**不要计入失败数量** |
| `RUN_RECHECK` / `RECENT_REPORT_ONLY` | 本库只有历史讨论/阶段报告或近期对话摘要；采用数值或做新决策前须核原始Run、协议、数据身份和独立统计单位 |

任何历史`PASS/FAIL`至少区分**工程、数据有效性、科学机制、真实任务、论文贡献**五种含义。负结论须记录`DECISION_SCOPE=RUN/MECHANISM/CLAIM/PROJECT`；未经验证记`UNKNOWN`，不可编造Git SHA或已获授权。

## I. 更新与去重原则

- 新结果应附`project_identity / claim_id / run_id / commit / data&protocol_id / baseline / metric / independent_n / result_scope`；未知填`UNKNOWN`，不要杜撰ID。
- 最新、同一版本的**原始Run**优先于旧聊天摘要；若原结果后来被修正，更新本表并保留变更依据。
- **单一项目多个机制可以分别止损，但不能算独立项目失败次数**；同名P1/任务序号不具有跨聊天唯一性。原01–23不重编号；本次24–27是新增身份，不是新增4个整体失败。
- 若开发数据/原test已经用于方法选择，不能重命名成`untouched holdout`；任务更换、指标口径改变或holdout被查看都需核新的确认资格。
- 最近实验报告与原始Run不一致时，**以原始Run、协议和模型版本为准**，保留修订的时间点，不能用后来发现反向冒充早期先验。
- 本文用于避免重复错误，**不是反向禁止创新**，更不是对投稿成功概率的统计估算。保持小规模有判别力的探索与真实授权门禁。

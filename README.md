## 使用方法

1. 根据下表选择最接近的任务，每个具体步骤优先选一条 Prompt；跨阶段任务可顺序使用，如 S01 发现候选 → S02 核查资格 → G02 撰写申请书。
2. **第八项是例外**：优先只复制一次 [START.md](08_算法检验与优化/高水平计算机论文工作流/START.md)，后续由具备 GitHub 访问能力的 Agent 按状态读取；其他类别打开文件，复制 **「可直接复制的 Prompt」** 代码块。只填写与你本次任务有关的【参数】，已有资料可直接粘贴或上传，不必复制整页说明。
3. 需要实时事实核查时使用可用的联网工具并保留官方证据；已有上传文件可先在可读范围内审查。工具不可用时明确未核查，不要假称完成。
4. 多轮协作时，保留研究背景与最终版本，尽量不要重复添加互相冲突的长指令。
5. 当发现可复现的输出问题时，先在 [EVALUATION.md](EVALUATION.md) 固定测试输入和验收条件，再做有针对性的修订；不为了版本号或文本篇幅增加新模板。

## 来源透明度

本项目参考 **公开 GitHub 仓库中的文字 Prompt，以及 Skill/Agent 的公开任务组织方法**，但主要收录独立改写的文本 Prompt；v4.1 新增本库自写的可选路由 `SKILL.md`（不会自动安装），不嵌入第三方 Skill 原文。Fabric 虽然有软件实现，这里仅参考其公开 `data/patterns/*/system.md` 纯文本提示词。

**重要区别**：这些并不是从 GitHub 原文一字不变搬来的 20 份模板。具体实践中不存在每个任务都有一份成熟高星 Prompt，因此采用“阅读原文 → 提炼任务组织逻辑 → 针对科研场景重写”的方式。每个文件底部给出匹配的 Prompt 页面及改编性质。尤其是日本基金的三项、科研对话高保真接力、Codex审计、日语作文比赛，均属于**跨场景原创改写**，不能误以为 GitHub 有成熟的高星同名模板。V01—V03 在 v1.7 改为指向 v4.1 的兼容入口，避免重复维护；V02/V03 路径保留。

如果你只需要最优先六条：`S01`、`G02`、`G03`、`P03`、`L01`、`M01`。

## 不要继续拆分的项目

- 四个翻译方向合并为 `L01`，使用参数指定语言和文体。
- IMRaD 各章节合并为 `P02`，使用 `Section` 参数。
- S01 保留一个兼容入口，但按目的提供两套独立可复制指令：**A 基金、奖学金与科研资助**，**B 通用信息**。单个资助项目的条款核实仍转 `S02`，不复制两套 Prompt 一起发送。
- 日英写作润色与消除机械表达合并为 `L02`；科学内容独立由 `P03` 和 `G03` 审查。
- 基金的每个栏目不新建文件，在 `G02` 中依据官方表格逐栏处理。

## 质量底线

- 对文献、截止日期和资助规则，必须使用原始来源核实，不能编造引用。
- 对缺失文件、未运行实验和读不到的聊天，不得声称已经查阅。
- 统计结果必须保留样本量、单位、区间、随机种子和验证状态；模拟不等于实测。
- 文字自然化是修辞改进，不是规避 AI 检测或绕过机构的 AI 使用规则。
- 各开源来源的许可证不同，本库是针对个人场景撰写的新提示词；如未来公开二次发布 GitHub 原文，应逐个检查原仓库授权和署名条款。

详见 [SOURCES.md](SOURCES.md)（来源列表与热度快照）和 [00_使用规范.md](00_使用规范.md)。

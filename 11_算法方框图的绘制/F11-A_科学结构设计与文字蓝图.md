# F11-A｜Step 1：科学结构设计与文字蓝图

> **你 → ChatGPT**。目标是把论文方法凝练成可审核的算法框架图方案；本阶段**不绘图、不调用 Codex、不生成 HTML/SVG**。可同时提供论文 Methods、现有算法说明和喜欢的参考图。

## 可直接复制的 Prompt

```text
请根据当前论文/算法资料，为 Fig.X 设计一份可直接用于后续绘图的**文字版科研框架图蓝图**。我提供的参考图只用于借鉴信息层级、区域布局、留白和设计节奏，不照搬其算法、公式、模块或箭头。

【科学抽象】
1. 用一句话确定这张图最需要解释的核心创新或机制。
2. 从真实方法中筛选：P0 必须画（核心输入、机制、输出、必要依赖与隔离）；P1 按需画（关键公式、分支、反馈）；P2 默认不画（普通预处理、参数、代码细节、重复说明）。能合并的步骤封装进父模块，不把伪代码逐行画成框。模块数量以解释完整性为准，勿机械限数。
3. 明确数据流、参数/模型依赖、控制或反馈关系及评价专用输入；区分实际存在的训练、校准、推理、测试/评价阶段。不能把并行画成顺序，不能让测试真值或未来信息流入不允许的阶段。
4. 只依据提供的证据设计；缺失的关键关系标注“待核实”，不得臆造科学机制或实验结果。

【布局思路】
给出简洁的总体构图建议：一条易读的主流程，必要时设置顶部机制条、侧边状态/资源区、右侧结果区、底部公式/反馈区。只有科学上确实存在对应机制时才设置这些区域；考虑后续设计增强的空间，但现在不放插图。

【只输出以下六项】
① 图的一句话主旨；
② 一级模块及必要的二级信息（给每个科学模块稳定 ID，如 N1/N2；文字尽量短）；
③ 有向连接清单：起点 ID → 终点 ID｜含义（数据/参数/控制/评价等）｜是否必须标注；
④ 一处推荐版式及核心创新的视觉重点；
⑤ 合并/省略的内容及原因；
⑥ 原则性逻辑风险与“可交付给 Codex 的最终蓝图”（以②③为唯一科学结构基准）。

本阶段只出方案，不出图形代码。默认只有这一次科学结构确认，不设置额外的形式化审核节点。
```

## 交接与使用

请先确认这份 **Figure Blueprint** 的科学模块、公式和连接关系。确认后在同一对话发送 F11-B；若换对话，只需粘贴最终蓝图，不必重复整篇论文。科学结构未确认前不应进入大规模 SVG 布局。

# F11-B｜Step 2：基础方框图的 Codex 指令生成

> **你 → ChatGPT → Codex**。在 F11-A 的文字蓝图得到确认后使用。本阶段仅把已确认的科学结构实现为**几何图形、文字、公式与箭头组成的基础 HTML/SVG**；不进行插画式设计增强。

## 可直接复制的 Prompt

```text
已确认 Step 1 的 Figure Blueprint。请你**只为 Codex 编写一份可直接执行、尽量省 Token 的基础绘图指令**，而不是自己绘图或重新设计算法。优先使用本对话的最终蓝图；如果无法访问，我会提供已确认的蓝图。

请让 Codex：
1. 只读取必要的蓝图与项目文件，直接生成/修改 HTML（内嵌原生 SVG）和独立 SVG，保持离线可打开、可编辑。若已有合适的生成源代码，复用而不是重写；HTML/SVG 本身也属于可编辑源代码。
2. 按蓝图绘制准确的科学节点与有向连接；在 SVG 中为模块和连接使用稳定 ID。只用方框、分组、文字、必要公式、实线/虚线与有限浅色。不画人体运动、复杂场景、机器人、装饰性图标，不访问 SVG 资产库。
3. 采用清楚的主线和少量必要分支，区分实际存在的数据流、模型依赖、并行/顺序、反馈、评价专用输入。不要擅自增删方法模块、公式或依赖；发现蓝图存在重大矛盾时标出问题，不靠编造关系补齐。
4. 保存轻量的结构基准（模块 ID、连接起点/终点及类型、关键公式/标签），供 Step 3 比对，避免美化过程改变算法。
5. 做一次定向检查：节点/箭头与蓝图逐项对应；无泄漏或错误依赖；文本可读、端点准确、无遮挡。具备渲染工具时预览一次；否则注明“视觉未验证”，不要假称已验证。

【交付】
- 基础 HTML（内嵌 SVG）、独立 SVG，以及必要的结构基准/现有生成源码。
- 仅报告产物路径、科学结构检查结果与仍未确定的关键问题；不输出长日志、PNG/PDF 或重复方案分析。

这一版即使不够美观也可以；**科学逻辑正确和关键要素不缺失**优先于美观。请只返回给 Codex 的最终指令。
```

## 交接与使用

把本文件的 Prompt 发给 ChatGPT，由 ChatGPT 生成给 Codex 的任务指令；然后在 Codex 中运行。保留基础图及结构基准，供 F11-C 在同一工作区继续使用，避免重复读取 Methods 或从零画图。

# F11-B｜Step 2：基础结构与矢量实现指令

> 用户 → ChatGPT → Codex：将已确认的蓝图转换为独立执行的完整 Codex 指令；本步确保科学表达正确及后续原生可编辑性，不追求最终审美。

## 可直接复制的 Prompt

```text
现在进入 F11 第二步。基于本对话中已由我确认的最终 Figure Blueprint，生成一份可直接交给 Codex 的完整基础绘图指令。ChatGPT 本轮只写指令，不绘图。无需重新上传论文、Methods、算法代码或参考论文；若确实缺少最终蓝图，只指出缺少该蓝图，不要求重复提交原文。

【指令必须包含三部分】

1. 使用 Skill
- 优先使用用户此前指定的绘图 Skill，明确名称、已知路径/来源、用途；未指定时使用 svg-figure（SVG 绘制、文字对齐、布局与基础验证），来源：
  https://github.com/neuromechanist/research-skills/blob/cf52ffe6e518281ec574f2e1b4365c8bdf467d6f/plugins/figures/skills/svg-figure/SKILL.md
- 本地可用时按需读取；未安装但文档可访问时作技术参考；均不可访问时直接用原生 HTML/SVG 并如实说明。不得假称已安装，不自动下载安装整个工具链。Skill 不得覆盖科学蓝图。

2. 针对本图的完整绘图方案
- 直接写清 Figure Profile（项目/论文、figure_id、蓝图版本、图形类型、核心主旨、目标期刊、最终显示尺寸及最小可读字号）。目标未知时沿用蓝图的暂定值，不当成期刊规范。
- 写明所有必要 N-ID、科学作用、应展示的英文标签、公式、数值，以及 E-ID 对应的真实关系类型、方向（如适用）、标签和依赖；保留已确认 P0 与选定 P1 的展示义务：MUST_SHOW 在图中可识别，MUST_PRESERVE 在结构中遵守而不强制写出，OPTIONAL 按需取舍，OMIT 不画。
- 给出关键 F-ID、单位、统计分母、数据集与证据性质、冻结状态、训练/校准/推理/评价边界、禁止依赖及仍未解决的实质风险（仅适用时）。
- 写清主阅读路径、分区、核心创新、推荐视觉编码及可合并/省略的 P2。按图形类型自主选择机制示意、并列比较、数据图、流程等表达方式。
- 科学语义完整不等于一节点一框、一关系一箭头。允许用共享连接、分组、标签、公式、包含或空间对应表达；有方向的关系须清晰无歧义，不能用视觉合并隐藏关键关系。
- 指令必须自包含，不能只写“参照第一步”、只列 ID 或留下待填模块。严格忠实于已确认蓝图，不让 Codex 重新解读论文或选择研究方案。

3. 绘图实现与验收
- 原生 SVG + 自包含 HTML。用可编辑文字、几何形状、必要公式、连接及真实数据图完成基础图，P0 完整、选定 P1 简洁、P2 不画；有主次、合理留白，不机械堆方框。示意与真实结果须区分。
- 参数化几何（须落实到坐标计算与源码）：先定义基础单位 u、外边距、组间距、内边距、线路净空、圆角、线宽、对齐容差和字号；共享参数计算同级位置/尺寸，避免逐个手摆。建议外边距/组间距 2–3u、卡片间距/内边距 1–2u、线路净空约 u、几何对齐容差 ≤0.1u，按画布及科学结构合理调整并说明例外（内部默认值，非期刊要求）。同级功能区标题有归属、等地位卡片默认等宽等高，允许因内容或科学权重合理调整；不强制三栏或每个概念一框。
- 连线先规划通道再绘制：流程/架构连接统一水平或垂直直线、90° 正交折线；需要转向时必须有清楚拐角，不用任意斜线或曲线（真实物理轨迹/统计曲线不受此限）。默认从源框对应边中心正交出发、垂直于目标边界进入，多个端口用对称且有序的独立锚点；实际端点须对应科学节点而非无关容器。同类并行分支/汇聚优先采用真实共享主干、统一分支高度及明确接点；不同语义线路禁止无意共线或误汇聚。先绕行，无法避免交叉时用线桥或清晰断开区分不相连。禁止穿文字/图标、压框、贴边滑行、箭头悬空/截断；预留通道、合理图层，检查箭头尖端而非仅线段终点。
- 文字：独立框内的居中标签/公式须按真实多行文本块水平与垂直居中，留出安全内边距；列表、图表标签等按语义左/右/基线对齐。用统一字号、字重、行距、换行和文字宽度；核对真实数学字符、大小写、上下标（如 κ 不可换成 k/K）及原始术语，不以近义标签改变科学定义。数据、标题、图例、单位/分母说明必须归入同一图表组。
- 本步不使用机器人或装饰 SVG 资产，不追求最终配色及特效；从开始考虑 Draw.io 原生对象映射：文字、形状、比例条及语义连接可独立编辑，避免复杂滤镜和文字转路径。第三步必须交付原生 .drawio，本步不要求提前生成。
- 科学交接门禁：生成轻量 figure_structure.json，含 figure_id、项目/论文标识、蓝图版本、尺寸/字号、稳定 N/E/F-ID、端点/方向/类型、展示义务、公式/数值/分母/单位/证据、隔离/禁止依赖；保留可访问的已确认蓝图或其完整科学合同快照（可内嵌 JSON，不强制新增文件）。先逐项对照用户确认蓝图，检查 ID 唯一、必要内容和引用完整、无新增科学语义，再冻结；记录冻结文件 SHA-256 或等效内容校验值于现有源码/交接说明，不把自引用哈希写进被哈希文件。科学合同与视觉映射分离，允许多对多映射；后续视觉变化另记，不覆盖原文件。发现不一致先修复转录错误，真正科学矛盾报告并暂停受影响部分，不自行改变蓝图。
- 在该 figure_id 的独立目录（如 figures/Fig01 或 figures/Graphical_Abstract）输出 figure_base.html、同内容的 figure_base.svg、figure_structure.json；核对项目/图号/版本，避免覆盖其他图。按需保存共享布局或生成脚本，不强制复杂工程。SVG 明确 viewBox/尺寸、使用常见可用字体及标准 text/tspan，避免不必要的 foreignObject、外部字体或在线公式依赖；HTML 内联同一 SVG 及资源。允许临时预览，不正式导出 PNG/PDF。
- 集中验收：蓝图→JSON→基础图逐项核对；用共享坐标、实际文本边界及路径检查对齐容差、文本安全边界、线路净空/端点、遮挡与越界（考虑变换、描边和 marker，排除有意包含/接触）。工具可用时实际渲染并打开图像分析，不以文件生成代替视觉检查；发现明确缺陷集中修复再复查。实质科学矛盾报告，普通实现自主处理；未执行的验证标未验证，不声称通过。交接时给出文件路径、冻结校验值及关键检查状态，不加额外审批。

【最终只输出】一份可独立发送给 Codex 的指令，含“使用 Skill”“本图详细方案”“绘图实现与验收”三部分，所有具体科学内容已填好。要求 Codex 连续完成，不反复规划或启动额外 Agent，最终仅报告文件路径、关键验证结果与未解决问题。节省 Token，不以删减必要科学关系为代价。
```

# F11-B｜Step 2：基础方框图 Codex 指令生成

> **用户 → ChatGPT → Codex**：用 F11-A 已确认的 Figure Blueprint，生成可编辑的基础 HTML/SVG。ChatGPT **只输出给 Codex 的指令**，不自行绘图；本阶段不调用 SVG 插图资产。

## 可直接复制的 Prompt

```text
请基于已经由我确认的 F11-A Figure Blueprint，给 Codex 生成一份精简、可立即执行的“基础框架图”绘图指令。你只编写 Codex 指令，不重新设计科学方案，也不亲自绘图。

【交接】Codex 未必能看到本聊天：若 Blueprint 已在其工作区，给出具体可访问文件路径；否则把绘图必需的 N/E/F/数据隔离条件紧凑地放入 Codex 指令中。不能只写“按之前确认的方案”。没有可用的科学结构依据时，不要让 Codex 自行发明。

【要求 Codex 连续完成】

1. **科学结构优先**：读取已确认的 Figure Blueprint 与必要项目文件，使用几何框、分组、简短文字、必要公式和有向箭头绘制基础 HTML（内嵌 SVG）及独立 SVG。两者保持一致、离线可用、可编辑；优先复用已有代码，不开发不必要的绘图框架。

2. **信息凝练**：只展示足以解释论文核心工作与重要创新的内容。P0 必须表达，P1 尽量合并展示，P2 默认省略。不要逐项绘制所有预处理步骤、超参数、中间变量和重复公式。普通说明可以合并，但不得擅自删除或合并 Blueprint 已确认的科学节点、关键依赖和数据隔离；如需改变科学结构，应先修订蓝图。

3. **简洁布局与留白**：优先建立一条清晰的主流程，辅以必要的分支或状态区域。主流程可从约 4–7 个主要视觉单元开始设计，但不设硬性数量上限。每个方框优先只放标题和一项必要说明。不要为了填满画布而添加内容；允许主流程周围、模块之间及辅助区域存在明显留白。辅助机制应简洁表达，不要过度拆分。

4. **准确表达依赖**：SVG 科学节点使用稳定 N-ID，连接使用稳定 E-ID。明确数据流、参数/模型依赖、并行与顺序、反馈及 evaluation-only 关系。不可为了简化画面而隐藏关键箭头、改变方向或混淆训练、推理与评价边界。本阶段不使用机器人、装饰插图或 F11 SVG 资产。

5. **保存结构基准**：生成轻量的 figure_structure.json，包含 nodes（ID/关键标签/阶段）、edges（ID/from/to/type/必要标签）和 invariants（关键公式/符号、冻结状态、数据隔离及禁止连接）。只记录科学语义，不保存视觉坐标、颜色或装饰容器。

6. **基础图验收**：对照 Blueprint 检查节点、连接、公式和科学边界完整且正确，同时检查是否存在冗余方框、重复标签、局部拥挤、文字遮挡或辅助内容喧宾夺主。确保主流程容易识别，必要内容充分但不过量。工具允许时完成一次 SVG 解析与浏览器预览；无法执行的检查注明“未验证”。存在重大科学矛盾时报告问题，不擅自编造修复。

本阶段的目标是：**科学正确、核心内容清楚、结构简洁、留白合理，并为下一阶段保留足够的视觉设计自由度。**

【Skill 使用规则】可以利用绘图 Skill 的字体、SVG 排版及渲染技巧，但已确认的 Blueprint、用户明确要求优先于 Skill 的默认风格。不要为满足 Skill 模板增加科研模块或复杂装饰。

【默认交付】figure_base.html、figure_base.svg、figure_structure.json；已有项目有固定文件名时沿用该约定。只报告实际产物路径、结构一致性检查、未解决的原则性问题。此阶段不需要漂亮，也不输出 PNG/PDF 或长日志。

请直接给出一份可复制给 Codex 的指令，避免再附加分析。
```

## 使用与交接

让 Codex 在同一工作区保存基础图与 `figure_structure.json`。F11-C 直接复用，不重复分析整篇 Methods。基础图可被重新排版，结构基准只锁定科学含义，不锁定画面坐标。

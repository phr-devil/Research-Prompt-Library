# F11-C｜Step 3：全局视觉设计、Draw.io 工程与最终验收

> 用户 → ChatGPT → Codex：完成有整体构思的科研图，同时强制交付原生可编辑 Draw.io、SVG 和 HTML。第三步内完成设计与验收，不设置第四步。

## 可直接复制的 Prompt

```text
请基于 F11-A 已确认的 Figure Blueprint、F11-B 基础 HTML/SVG 与 figure_structure.json，以及我提供的审美参考图，为 Codex 编写一份精简、自包含的最终绘图指令。ChatGPT 只输出 Codex 指令，不亲自绘图、不重新选择科研方案。

【参考图交接与 Skill】
若参考图有 Codex 可访问的真实路径，明确写出；否则从当前可见图片提炼具体 Visual Brief（主阅读动线、视觉焦点、主次比例、留白、容器、线条、配色、图标风格和信息密度）。没有参考图时，根据科研内容与期刊自主设计，不假装看过图片。只借鉴视觉语言，不复制科研机制。
继续使用用户指定 Skill 或 svg-figure：
https://github.com/neuromechanist/research-skills/blob/cf52ffe6e518281ec574f2e1b4365c8bdf467d6f/plugins/figures/skills/svg-figure/SKILL.md
并参考 Draw.io 官方生成规范：
https://www.drawio.com/docs/reference/diagram-generation/
按需读取可用 Skill/文档；无法访问则用原生 SVG/mxGraph XML，并如实说明。不自动安装工具链；Skill 不覆盖科学语义。

【要求 Codex 连续执行】

1. 科学冻结、视觉开放：读取基础图及 figure_structure.json，保留所有冻结 N/E/F 科学语义、必要标签、方向/类型、公式、真实数值、单位、分母、证据性质和隔离/禁止依赖。允许改变全部坐标、形状、大小、容器、箭头路径、视觉编码及宽高比（仍需满足目标尺寸）。不强制一节点一方框、一关系一箭头；共享连接、分组、标签、公式、机制示意或定量图均可，但映射须可追溯、科学关系须无歧义。视觉容器不得被误读为新机制；不重新引入已省略的细节，不虚构科研成果或改写原结构文件。

2. 全局构图：在生成的 Codex 指令中直接写明本图的具体科学叙事、创新焦点、主阅读路径、功能区域、主次比例、视觉编码、重要标签/公式/数值和可弱化内容。根据图形类型选择布局：Graphical Abstract 强调核心发现与小尺寸可读性；Architecture 强调真实机制/数据流/隔离；Mechanism 强调物理结构与过程；Workflow 强调实验顺序、条件与对照；Results 强调真实数据、坐标、单位与统计证据。允许组合，不机械采用三栏、方框或插画。先整体构图、视觉层级和留白，再设计局部形状与配色，最后添加必要插画。不要填满画布或重复已经用图形表达的文字。

3. 统一视觉主题：优先复用当前论文已确定的 Figure Theme；用户明确指定优先。没有主题时从三套科研配色中选一套，默认 A；需要更高状态辨识度时可选 B，插画型可选 C。依据 references/F11-C_科研配色方案_三套.md（若可访问），在 Codex 指令中直接填入选定配色及语义映射，不要求 Codex 加载其余两套。
   - A｜Paul Tol Pale：原始浅填充 #AACCEE、#BBDDBB、#EEEEBB、#EEBBDD；对应 F11 适配深描边 #3D6B9D、#228833、#857828、#8A518A（非原始 Tol 色值）。
   - B｜Okabe–Ito：原始强调色 #0072B2、#009E73、#D55E00，可选 #56B4E9；对应 F11 适配填充 #EAF4FA、#E8F6F1、#FFF1E7。
   - C｜ColorBrewer Set2：原始色 #8DA0CB、#66C2A5、#FC8D62、#E78AC3；F11 适配填充/描边 #EEF1F9/#6879A5、#EAF6F1/#368C74、#FFF0E8/#C86F4F、#FBEAF5/#B86796。
   - 通用中性色：页面 #FFFFFF、辅助背景 #F7F9FB、主文字 #243447、次文字 #5B6B7C、箭头 #44576A、辅助虚线 #A5AFBA。
同类语义跨图同色，不随机混合不同来源色板，通常 2–3 个功能色，必要时增加状态色。颜色不是唯一识别方式，配合文字、线型、符号或形状；不假定适配色均色觉安全。统一字体、字号层级、线宽、圆角、间距与箭头。圆角矩形（参考半径 8–12 px）、大圆角容器（12–18 px）、浅底深字和细描边只是默认语言，按实际画布调整，不限制视觉形式。特殊形状须有科学语义，避免厚重阴影、复杂渐变、无意义 3D。必要时保存轻量 figure_theme.json 供同一论文复用，不重复生成。以实际期刊排版尺寸而非放大浏览器判断可读性；未知期刊要求标暂定，不虚构强制标准。

4. SVG 素材最后添加：按需读取 F11 assets/manifest.json 和选中素材的许可证，按 style/concepts 定向选择。Robot Toast 仅在有角色/智能体等语义价值时使用；通用图标通常只选择 Lucide、Tabler、Phosphor Duotone 中一个系列；OpenMoji 少量使用并遵守许可。无合适素材时原生 SVG 手绘。不强制每个框有插画，不添加无关硬件或装饰；保持等比缩放、离线内联、ID/引用正确及来源许可清楚。

5. 原生 Draw.io 与跨格式交付（强制）：从全局设计阶段考虑原生可编辑性，使用共享布局、样式、数据或生成脚本统一输出三种格式，也可采用 Draw.io 原生布局为基础再生成 SVG/HTML。简单图直接生成即可，不强制额外布局文件。避免各格式分别设计造成漂移。
   - figure_final.drawio 使用有效原生 mxGraph XML（优先未压缩 mxGraphModel），主要方框、容器、文字、数值、公式及简单数据图形可独立编辑，语义连接线应真实绑定对应节点；非方向性关系不得伪造箭头。
   - 公式用可编辑文本或 Draw.io 支持的数学排版，保持符号及上下标。复杂矢量插画允许局部内嵌 SVG，禁止整图或主要科学内容作为单一图片嵌入后宣称可编辑。
   - 保留 N/E/F-ID 或明确映射；原 figure_structure.json 不改写，变化的视觉映射另记于共享布局或源文件中。资源自包含，避免网络依赖。
   - SVG 独立可用，HTML 内联同一 SVG。允许渲染引擎造成轻微外观差异，但科学内容、整体布局、视觉层级和主要关系须一致。

6. 集中验收：以冻结结构为基准核对科学语义、必要关系、公式、数值、单位、分母、隔离与禁用依赖；检查主焦点、阅读动线、留白、图形比例、颜色对比、字体、重叠、遮挡、越界及箭头端点。对 Draw.io XML 进行有效性、唯一 ID、父子关系、source/target 引用和主要对象可编辑性检查，核对三个格式。工具可用时必须实际渲染整图及目标论文尺寸，尽可能在 Draw.io 打开/预览并验证连接与编辑；允许临时 PNG/截图，不作为正式交付。无法执行渲染或交互验证时如实标注未验证，不把静态检查说成实测通过。默认一次集中检查、修复及复查；实质问题继续定向处理，不无限循环、不产生多个方案、不重新索取论文。若目标尺寸与必要科学内容冲突，先压缩重复视觉内容，仍不解决则报告，不擅自删 P0 或已冻结 P1。

【最终交付】
在第三步内强制生成：
- figure_final.html（自包含预览）
- figure_final.svg（独立可编辑矢量图）
- figure_final.drawio（原生可编辑工程）
- 保留原 figure_structure.json（未改写的科学基准）
按需保留实际使用的布局/生成脚本、figure_theme.json、视觉映射及素材。保留基础图，非必要不生成额外工程或正式 PNG/PDF。缺少 .drawio、主要内容不可编辑或科学结构存在实质错误，不得标记完成；不可执行的验证明确区分未验证与失败。

【ChatGPT 最终只输出】一份能直接交给 Codex 的完整指令：包含具体视觉 brief、本图设计方案、选定主题及交付验收要求。冻结结构可直接读取时不全文复述，但必须写清关键内容；无可访问路径时不要假定 Codex 共享聊天。要求自主连续完成设计、原生工程、多格式输出及必要修复，最终仅汇报文件路径、关键设计变化、科学/跨格式一致性、Draw.io 可编辑性/实际渲染验证状态及实质未决问题。
```

```text

【先完成参考图交接】
Codex 不一定能看到本对话上传的参考图片：如果 Codex 有可访问图片路径，在指令里明确写出；否则先从我提供的图片提炼一段具体的视觉 brief（如横向主视觉动线、主次区域、留白、分组容器、细描边、低饱和色、插画相对比例）并写进 Codex 指令。不得假装 Codex 能读取未提供的图片。参考图只提供视觉组织，不复制其算法节点、符号或箭头。

【要求 Codex 连续执行】

1. **锁定科学结构，开放视觉设计**：读取基础 HTML/SVG 与 figure_structure.json，保留所有科学节点、连接方向与类型、关键公式、冻结状态和数据隔离。允许重新安排全部视觉坐标、方框尺寸、容器分组、箭头路径与整体长宽比例，但不得改变科学含义。纯视觉容器不应被误读为新的算法模块。

2. **先完成整体构图设计**：根据参考图提炼适合本论文的视觉方案，明确核心创新的视觉焦点、主阅读路径、主次模块比例、功能分区及留白区域。优先突出主流程，将辅助状态、资源、评价和反馈机制进行适度弱化。可以借鉴参考图的顶部机制条、侧边容器、底部公式区等设计，但只有算法真实需要时才采用，不机械复制固定版式。

3. **控制信息密度与留白**：设计感来自清晰的信息层级、空间比例和视觉节奏，而不是填满画布。不要让图片的每个区域都有内容；不强制每个模块都出现公式、标签或插图。优先保留核心科学信息，减少重复说明和次要装饰。允许明显留白，避免局部方框、文字、箭头和插图过度密集。视觉增强不能重新引入 Step 2 已省略的普通实现细节。

4. **统一图形形状**：
   - 普通算法模块：默认圆角矩形，圆角半径约 8–12 px。
   - 阶段分组和功能容器：大圆角矩形，圆角半径约 12–18 px。
   - 核心创新模块：采用相同圆角语言，但可通过尺寸、位置或配色增加视觉权重。
   - 公式与评价区域：采用简洁的圆角框或适当的胶囊形容器。
   - 数据存储或特殊结构：只有语义明确时才使用圆柱体、树形图等特殊形状。
   - 箭头：优先清晰的直线、折线和有限曲线，减少交叉。

   避免默认使用生硬的直角矩形、厚重阴影、复杂渐变和 3D 效果。以上尺寸按 SVG 实际画布尺度合理调整，不机械固定像素。

5. **科研配色规范（默认 Palette A）**：

   背景与中性色：
   - 页面背景：#FFFFFF
   - 辅助区域背景：#F7F9FB
   - 中性容器：#F2F4F7
   - 中性描边：#D7DEE7
   - 主文字：#243447
   - 次文字：#5B6B7C
   - 主箭头：#44576A
   - 辅助虚线：#A5AFBA

   功能色系（填充 / 描边）：
   - 柔和蓝色：#EAF3FA / #7EA6C8
   - 浅绿色：#EBF5EF / #83B89B
   - 暖米黄色：#FFF5E8 / #D4AD65
   - 淡紫色：#F3EFFA / #A895C7
   - 可选浅红色：#FCEEEE / #D97A73

   一张图通常使用 2–3 个主要色系，其余仅作少量强调。颜色根据当前算法的实际模块语义统一映射，不机械规定所有论文必须使用相同的功能配色。同类模块采用同一色系。避免高饱和大色块，确保文字、公式及箭头具有足够对比度；不能只依靠颜色区分关键连接关系。

6. **SVG 素材最后添加**：先完成整体构图、圆角形状、配色和留白，再考虑插图。读取 F11 assets/manifest.json，按 style/concepts 只选择真正需要的素材。Robot Toast 用于核心角色，Lucide、Tabler、Phosphor Duotone 通常只选择一个系列作为通用图标，OpenMoji 仅少量强调且须遵守其许可证要求。插图必须具有语义价值，并与整图风格一致。已经拥挤、包含较多文字或公式的模块不再强行加入插图。使用可编辑原生 SVG，等比缩放、离线内联，并正确处理内部 ID 及其引用，不复制来源或许可不明的素材。

7. **最终验收**：对照 figure_structure.json 验证科学节点、边和关键约束未改变；再检查主流程是否突出、辅助区域是否适度弱化、颜色和圆角是否统一、留白是否合理、是否存在不必要的视觉元素。检查文字、公式、箭头端点、插图与容器边界有无重叠，并在工具允许时预览整图及缩小到论文排版尺寸后的效果。针对明显问题集中修正并复查，不反复生成多个方案；无法验证的事项如实说明。

最终目标：**生成一张具有明确视觉构思、布局节奏、统一科研审美和适度插画表达的论文方法图，而不是一张简单添加图标或填满内容的方框图。**

【Skill 与交付】Skill 只提供技术实现建议，不得覆盖蓝图或强制重设计。优先在现有 HTML/SVG 和源码上编辑；仅在基础布局限制设计质量时才重构视觉代码。最终输出自包含 figure_final.html、独立 figure_final.svg 和实际用到的源文件（如有），保留 figure_structure.json 作为未改写的语义基准；不自动导出 PNG/PDF。

只给出一份能直接交给 Codex 的指令，尽量节省 Token；Codex 最终仅汇报文件路径、设计关键变化、结构一致性检查及未解决事项。目标是有明确视觉构思的学术图，而非“装饰过的方框图”。
```

# F11-C｜Step 3：全局视觉设计、Draw.io 工程与最终验收

> 用户 → ChatGPT → Codex：完成有整体构思的科研图，同时强制交付原生可编辑 Draw.io、SVG 和 HTML。第三步内完成设计与验收，不设置第四步。

## 可直接复制的 Prompt

```text

【参考图交接与 Skill】
若参考图有 Codex 可访问的真实路径，明确写出；否则从当前可见图片提炼具体 Visual Brief（主阅读动线、视觉焦点、主次比例、留白、容器、线条、配色、图标风格和信息密度）。没有参考图时，根据科研内容与期刊自主设计，不假装看过图片。只借鉴视觉语言，不复制科研机制。
继续使用用户指定 Skill 或 svg-figure：
https://github.com/neuromechanist/research-skills/blob/cf52ffe6e518281ec574f2e1b4365c8bdf467d6f/plugins/figures/skills/svg-figure/SKILL.md

https://www.drawio.com/docs/reference/diagram-generation/
按需读取可用 Skill/文档；无法访问则用原生 SVG/mxGraph XML，并如实说明。不自动安装工具链；Skill 不覆盖科学语义。

【要求 Codex 连续执行】

1. 科学冻结、视觉开放：核对项目/figure_id、蓝图版本、基础图及 figure_structure.json；如有冻结校验值须验证。以用户确认蓝图或其已核验科学合同为最高基准，核对 JSON 转录及实际图形（不能仅验证 ID 存在）。发现冲突报告并暂停受影响的科学内容，不擅改基准。保留 N/E/F、方向/类型、公式、数值/单位/分母/证据及隔离/禁止依赖；MUST_SHOW 必须可见识别，MUST_PRESERVE 必须遵守但不强制写字，未选 OPTIONAL 可取舍，OMIT 不画。允许改变全部坐标、形状、大小、容器、箭头路径、视觉编码及宽高比（仍需满足目标尺寸）。不强制一节点一方框、一关系一箭头；共享连接、分组、标签、公式、机制示意或定量图均可，但映射须可追溯、科学关系须无歧义。视觉容器不得被误读为新机制；不重新引入已省略的细节，不虚构科研成果或改写原结构文件。

2. 全局构图：在生成的 Codex 指令中直接写明本图的具体科学叙事、创新焦点、主阅读路径、功能区域、主次比例、视觉编码、重要标签/公式/数值和可弱化内容。根据图形类型选择布局：Graphical Abstract 强调核心发现与小尺寸可读性；Architecture 强调真实机制/数据流/隔离；Mechanism 强调物理结构与过程；Workflow 强调实验顺序、条件与对照；Results 强调真实数据、坐标、单位与统计证据。允许组合，不机械采用三栏、方框或插画。先整体构图、视觉层级和留白，再设计局部形状与配色，最后添加必要插画。不要填满画布或重复已经用图形表达的文字。
   REVISION MODE（仍属本步）：用户提供已有图及标注/修改意见时，先定位标注所指元素与受影响关系，红框/红箭头等批注不得进入正式图。优先局部修复，保留未要求改变且无缺陷的布局、配色及语义；扫描同类问题、同步三个格式并复查。只有局部无法消除实质缺陷时才扩大重排，无需重跑 A/B。

【版式与几何硬约束（写入 Codex 最终执行指令，不得仅概括为“美观/对齐”）】
- 网格与分区：先确定统一对齐网格、画布边距、组间距、内边距及预留连线通道，再放置内容。主区域标题采用统一 header band 或标题栏，与对应功能区的可辨识外容器一体化（流程/框架图的同级分区须有统一边框或浅底分组）；禁止孤立漂浮的主标题或跨组归属不明的文字。图表/机制图可采用符合其图形类型的面板，不为每个小标签机械加框；外容器负责分区，内卡片负责模块，标题/公式/注释可直接排版。通常控制在两层可见容器，只有真实层级需要时才增加；去除冗余边框。标题栏、容器边界及内容起始线对齐；同层级有一致的尺寸/间距规则。
- 卡片与形状：同等语义地位的并列卡片使用等宽、等高、等内边距及统一内部模板（标题、图标、主数值、说明/公式的相应基线）；不同内容量或科学权重时可有意调整，但不得破坏对齐。为 panel、card、pill 等同级形状统一圆角、线宽、填充和边距。采用共享参数计算几何：定义 u、外边距/组间距（建议 2–3u）、卡片间距/内边距（1–2u）、线路净空（约 u）、圆角、线宽、对齐容差（建议 ≤0.1u），按画布及实际字高调整并记录例外；这些是项目默认值而非期刊规范。优先复用 B 的参数，改变时统一更新，不逐个手摆。留白有节奏，不压缩字形或靠加重边框填空。
- 正交连线：流程/架构的有向连接必须使用水平/垂直直线或 90° 正交折线（同轴直连无需强行加拐角；需要转向必须有清晰直角）。禁止无理由的斜线、任意曲线；物理轨迹、统计曲线等非流程线按真实语义表达。默认锚定源/目标对象对应边的中心，连接段与边界垂直；多路端口可采用有序、对称、可区分的锚点，分支点清楚。箭头尖端准确到达目标边界、完整可见，不悬空、不藏在边框下、不误接组容器或相邻节点。预留足够通道，避免线路与文字、图标、数据图及无关容器相交；禁止沿边框滑行、跨线叠压、无语义共线或难辨终点。同类并行分支/汇聚优先用真实共享干线、统一分支高度和明确接点（必要时加实心连接点）；禁止不同语义线路无意共线/误汇聚。无法绕开的非连接交叉用线桥或明确断开区分，检查图层顺序、完整箭头及线路净空。为实际存在的 data/parameter/control/evaluation 等定义一致线型、箭头、颜色及必要短标签/图例，不靠颜色单独区分；无语义的分隔线不得像连接。必要时重排而非硬塞线。
- 文字排版：框内独立标题/标签、公式或主数值默认水平居中，整体多行文本块垂直居中；图表标签、说明性列表等按用途左/右/基线对齐，不机械全图居中。按渲染后的文字边界而非单个 baseline/估算字符数对齐；标题、副标题、数值和注释采用统一字号/字重/行距，等类卡片对应文本基线一致。安全内边距至少足以容纳实际字体边界及缩放后的清晰空隙；文字不得贴框、压线、溢出或被裁切。长标签先合理换行、增宽或重排。按目标显示尺寸计算实际字号（SVG 字号×显示尺寸/viewBox 的有效缩放，含变换；印刷按物理单位换算），达到已确认/暂定最小字号；不靠压缩字形或继续缩小解决拥挤。公式使用真实希腊字母、上下标、数学乘号/减号及原始大小写，禁止 κ→k/K 等近似替换。逐项对照原始术语，不能把有效心率输出数简写成心搏数等不同测量对象。
- 图表与结果：相同尺度的比较图对齐起点、终点参考线及数值列，比例按真实数据；标签、图例色块、数值、单位、分母、数据集说明同组且对齐，明确统计口径。图例和分母说明贴近其数据图并纳入对应功能区，不散落画布。并列结论保持相同模板，因果/解释联系只按冻结语义表达，不为填空加箭头。所有数据可视化保留真实尺度/单位，不以图形比例夸大差异。

3. 统一视觉主题：优先复用当前论文已确定的 Figure Theme；用户明确指定优先。没有主题时从三套科研配色中选一套，默认 A；需要更高状态辨识度时可选 B，插画型可选 C。依据 references/F11-C_科研配色方案_三套.md（若可访问），在 Codex 指令中直接填入选定配色及语义映射，不要求 Codex 加载其余两套。
   - A｜Paul Tol Pale：原始浅填充 #AACCEE、#BBDDBB、#EEEEBB、#EEBBDD；对应 F11 适配深描边 #3D6B9D、#228833、#857828、#8A518A（非原始 Tol 色值）。
   - B｜Okabe–Ito：原始强调色 #0072B2、#009E73、#D55E00，可选 #56B4E9；对应 F11 适配填充 #EAF4FA、#E8F6F1、#FFF1E7。
   - C｜ColorBrewer Set2：原始色 #8DA0CB、#66C2A5、#FC8D62、#E78AC3；F11 适配填充/描边 #EEF1F9/#6879A5、#EAF6F1/#368C74、#FFF0E8/#C86F4F、#FBEAF5/#B86796。
   - 通用中性色：页面 #FFFFFF、辅助背景 #F7F9FB、主文字 #243447、次文字 #5B6B7C、箭头 #44576A、辅助虚线 #A5AFBA。
同类语义跨图同色，不随机混合不同来源色板，通常 2–3 个功能色，科学辨识度优先于默认色系，必要时增加状态色。状态色、普通结构色和中性色须分层；状态色不得用于无关装饰或造成不同状态混淆。颜色不是唯一识别方式，配合文字、线型、符号或形状；不假定适配色均色觉安全。统一字体、字号层级、线宽、圆角、间距与箭头。圆角矩形（参考半径 8–12 px）、大圆角容器（12–18 px）、浅底深字和细描边只是默认语言，按实际画布调整，不限制视觉形式。特殊形状须有科学语义，避免厚重阴影、复杂渐变、无意义 3D。必要时保存轻量 figure_theme.json 供同一论文复用，不重复生成。以实际排版尺寸检查字重、细线/箭头与对比度；优先深字浅底，普通文字对比度 4.5:1、关键非文字图形 3:1 可作内部设计目标（非统一期刊要求），检查灰度辨识及低透明度问题，必要时调整。期刊要求未知标暂定。

4. SVG 素材最后添加：按需读取 F11 assets/manifest.json 和选中素材的许可证，按 style/concepts 定向选择。Robot Toast 仅在有角色/智能体等语义价值时使用；通用图标通常只选择 Lucide、Tabler、Phosphor Duotone 中一个系列；OpenMoji 少量使用并遵守许可。无合适素材时原生 SVG 手绘。不强制每个框有插画，不添加无关硬件或装饰；保持等比缩放、离线内联、ID/引用正确及来源许可清楚。

5. 原生 Draw.io 与跨格式交付（强制）：在该 figure_id 独立目录中选定并记录唯一视觉实现基准（共享布局/生成源码或原生 Draw.io 工程），由其统一派生三个格式，禁止分别设计或单独改成品。简单图直接共享生成参数，不强制额外布局文件；每次修复先改基准，再同步全部格式。检查图号、版本、文件内容/生成记录，排除旧文件混用。
   - figure_final.drawio 使用有效原生 mxGraph XML（优先未压缩 mxGraphModel），主要方框、容器、文字、数值、公式及简单数据图形可独立编辑，语义连接线必须真实绑定对应节点；流程连接使用 orthogonalEdgeStyle 或等效原生正交路由、明确 source/target 与必要的 exit/entry 锚点及 waypoints，检查 Draw.io 自动路由未破坏视觉路径。非方向性关系不得伪造箭头。
   - 公式用可编辑文本或 Draw.io 支持的数学排版，保持符号及上下标。复杂矢量插画允许局部内嵌 SVG（说明其仅对象级而非路径级可编辑），禁止整图或主要科学内容作为单一图片嵌入后宣称可编辑。
   - 保留 N/E/F-ID 或明确映射；原 figure_structure.json 不改写，变化的视觉映射另记于共享布局或源文件中。资源自包含，避免网络依赖。
   - SVG 明确 viewBox/宽高比及背景（默认白底），使用可用且许可明确的常见字体、标准 text/tspan、离线素材；避免不必要 foreignObject、外链字体、在线公式和复杂滤镜。HTML 内联同一 SVG；检查字体回退、公式字符、裁剪与 Draw.io 自动换行/路由。仅允许轻微引擎差异，科学内容、整体布局、层级和主要关系须一致。

6. 集中验收（科学 + 几何 + 实际渲染 + 原生编辑，不能只检查文件存在）：
   - 科学：蓝图/已核验合同→冻结结构→实际图，核对展示义务、术语、节点关系、箭头端点/方向、公式/数值/分母及隔离，确认原冻结文件未变。
   - 几何：利用共享坐标、getBBox/文本测量、实际路径及 Draw.io cell geometry，按已定义容差检查同级对齐/尺寸、标题归属、文本安全区/居中、线路正交/净空/尖端/交叉、图表比例和画布边界。将坐标变换到统一空间，考虑描边、marker、裁剪；getBBox 本身不保证包含这些。区分有意包含/接触/真实共享分支与碰撞；不能仅以字符串存在或理想中心坐标宣称通过。
   - 渲染闭环：生成完整尺寸与目标论文尺寸的 SVG/HTML、Draw.io 实际渲染预览（工具可用时），必须使用图像读取能力打开并分析渲染图，核查整体叙事、文字真实大小/对比、局部拥挤、裁切、箭头及跨格式差异。仅导出截图、查文件大小、XML 合法均不算视觉审查。集中修复后重新渲染并实际查看受影响区域及最终全图。允许临时 PNG/截图，不正式交付；无渲染或图像读取能力则标未验证。
   - 可编辑性/一致性：验证 Draw.io XML、唯一 ID、父子关系、source/target/端口、主要对象原生可编辑；实际打开并在临时副本移动代表性节点验证连接（工具可用时，不修改交付版）。核对同次生成的三格式科学内容、布局和对齐，不能用 SVG 正常代替 Draw.io 实际验证。
   - 修复门禁：浮动分区标题、并列卡片无理由错位、文字明显不居中或溢出、流程线非正交/悬空/压线/贴框/指向错误、数学符号替换、图表标签归属或比例错误均为必须修复的明确缺陷。先集中修正，再针对失败项复查；无实质问题不反复迭代、不产生多套方案、不重新索取论文。若目标尺寸与必要科学内容冲突，优先合并冗余视觉表达、调整布局，仍无法解决则报告，不删冻结 P0/选定 P1。存在上述未修复缺陷不得标记完成。
   - 状态：逐项报告 Science、Geometry、Connectors、Typography、Hierarchy、Target-size、Editability、Cross-format、Visual inspection 为 PASS/FAIL/UNVERIFIED/N/A（N/A 只用于图形确实无此项，说明原因）。总状态 PASS 仅在所有适用必要检查实际通过且交付齐全时使用；PARTIAL 为文件已生成但必要检查未执行；FAIL 为存在已确认未修复缺陷；BLOCKED 为关键科学/实现条件缺失导致无法完成。已知失败不能用 PARTIAL 掩盖，不以主观审美评分替代证据。

【最终交付】
在第三步内强制生成：
- figure_final.html（自包含预览）
- figure_final.svg（独立可编辑矢量图）
- figure_final.drawio（原生可编辑工程）
- 保留原 figure_structure.json（未改写的科学基准）
按需保留实际使用的布局/生成脚本、figure_theme.json、视觉映射及素材。保留基础图，非必要不生成额外工程或正式 PNG/PDF。缺少 .drawio、主要内容不可编辑、科学结构或明确几何/文字/连线缺陷未修复，不能 PASS；必要渲染/交互未验证也不能 PASS。保留可交付部分并如实报告状态。

【ChatGPT 最终只输出】一份能直接交给 Codex 的完整指令：包含具体视觉 brief、本图设计方案、选定主题、上述版式与几何硬约束、原生 Draw.io 交付及验收要求；不得把硬约束压缩为笼统的“整齐、美观”。冻结结构可直接读取时不全文复述，但写清关键内容、版本及路径；稳定规则在 Codex 确有访问权限时可按固定版本/路径定向引用，否则内嵌必要硬约束，不假定共享聊天。要求自主连续完成设计、原生工程、多格式输出和修复，最终仅汇报文件路径、唯一视觉源、关键变化、总状态及各适用检查的简短证据/未验证项、实质未决问题。
```

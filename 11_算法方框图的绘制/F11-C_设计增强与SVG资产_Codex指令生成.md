## 可直接复制的 Prompt

```text

【先完成参考图交接】

【要求 Codex 连续执行】
1. **锁定科学语义，而非锁定坐标**：读取基础图和 figure_structure.json，保留 N/E-ID 所代表的节点、边方向和类型、关键公式、冻结状态、数据可见性、禁止依赖。允许重新设计所有位置、框体比例、路径、视觉分组、颜色与层次；普通容器/标题不是新的科研节点。若发现真实科学矛盾，报告并停止受影响修改，不臆造关系。
2. **先做整图设计，再选插图**：内部确定一个明确的版式概念——读者首先看到的创新焦点、主阅读路径、重要模块的视觉权重、辅助区域归属、公式位置和留白。借鉴参考图的视觉节奏，而不是机械套用“顶部条/侧边框/底部区”；设计要从科学信息中长出来。
3. **真正的视觉重构**：可大胆重排框体与分组、改善布局比例与空间节奏，建立清楚的主/辅层级，必要时用有限浅色容器与视觉标识区分功能。保持学术图的白底、清晰公式和细描边；避免平均分配所有方框、堆叠图标、华丽渐变、3D 和装饰型海报。
4. **资产只在有意义时使用**：先按 style/concepts 读取 F11 的 assets/manifest.json，再只打开实际需要的 SVG。Robot Toast 是统一机器人角色；通用小图标从 Lucide、Tabler、Phosphor Duotone 中优先选一种；OpenMoji 仅作少量强调，需检查 CC BY-SA 4.0 的署名、改编及投稿授权兼容性。素材必须与科学模块语义和整图风格兼容，不适合就不用。保持可编辑矢量、等比缩放、离线内联；遇到内部 SVG ID 时同步改写 id 和 url(#id)/href 引用，防止渐变或裁剪失效。不复制许可不明的外部插图。
5. **验收而非反复美化**：对照 figure_structure.json 检查 nodes/edges/invariants 不变（视觉容器与图形坐标不参与比较）；检查箭头端点、遮挡、标签与公式、缩放到论文排版尺寸后的可读性、素材风格和许可。工具允许时渲染整图及缩小视图，针对明显问题修正一次并复查；不能渲染则注明未验证。不要循环生成多个美化版本。

【Skill 与交付】Skill 只提供技术实现建议，不得覆盖蓝图或强制重设计。优先在现有 HTML/SVG 和源码上编辑；仅在基础布局限制设计质量时才重构视觉代码。最终输出自包含 figure_final.html、独立 figure_final.svg 和实际用到的源文件（如有），保留 figure_structure.json 作为未改写的语义基准；不自动导出 PNG/PDF。

只给出一份能直接交给 Codex 的指令，尽量节省 Token；Codex 最终仅汇报文件路径、设计关键变化、结构一致性检查及未解决事项。目标是有明确视觉构思的学术图，而非“装饰过的方框图”。
```

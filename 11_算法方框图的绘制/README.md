# 11｜算法方框图的绘制：三步工作流

**科学正确 → 基础图可验证 → 有全局设计感的科研图。** 用户分别给 ChatGPT 三段 Prompt：Step 1 直接产出可确认的文字蓝图；Step 2/3 由 ChatGPT 生成给 Codex 的执行指令。三个阶段不是三个独立审批点，**仅在 Step 1 对科学结构确认一次**。

| 阶段 | 提示词 | 阶段输出 | 最重要的边界 |
|---|---|---|---|
| [F11-A｜科学蓝图](F11-A_科学结构设计与文字蓝图.md) | 方法 + 参考图 → ChatGPT | N/E/F 稳定标识、关键公式/隔离、布局意图 | 参考图不提供科学证据 |
| [F11-B｜基础图](F11-B_基础方框图_Codex指令生成.md) | Step 1 已确认蓝图 → ChatGPT → Codex | **包含完整方案及明确 Skill 的独立 Codex 指令**；Codex 生成基础 HTML/SVG + `figure_structure.json` | 不再上传论文原文；只画几何骨架，不读取装饰素材 |
| [F11-C｜设计增强](F11-C_设计增强与SVG资产_Codex指令生成.md) | 蓝图 + 基础图 + 结构基准 + 审美参考 → ChatGPT → Codex | 设计版 HTML/SVG | 允许充分重排视觉，不改变科学节点、边和公式 |

## 执行与 Token 规则

- **上下文交接**：Step 2 必须由 ChatGPT 把已确认的蓝图**完整转述到 Codex 指令**（模块、箭头、关键公式/边界、布局），同时写明推荐 Skill 的名称和来源。Codex **不需要论文原文**，也不能假定能看到当前聊天。Step 3 的参考图片则须提供可访问路径或视觉 brief。
- **只锁科学结构**：`figure_structure.json` 是 Step 2 保存的轻量语义合同；Step 3 不锁定方框位置、大小和纯视觉容器，可以改变全局构图。
- **Skill** 只提供辅助绘图技巧，不覆盖用户与经确认的科学蓝图；默认少读文件、复用已有代码、同一 Codex 工作区连续完成第二/三步、少量定向验证。
- **快速修图**：已有满意图仅需修箭头或标签时，可直接局部修改，无须重新跑三阶段。

## 框架图设计原则

- **F11-B：少而清楚。** 只表达核心科学内容，避免把全部算法步骤、参数和公式都画进去。允许明显留白，不要求每个区域都有内容。
- **F11-C：少而有设计感。** 先优化整体构图、功能分区、视觉层级和空间比例，再采用统一的圆角形状与低饱和科研配色，最后按需加入 SVG 插图。
- **默认视觉规范：** 圆角矩形、细描边、白底深字、适当留白；[科研配色 A/B/C 三套方案](references/F11-C_科研配色方案_三套.md)（默认 Paul Tol Pale，另有 Okabe–Ito 与 ColorBrewer Set2），一次只选一套，通常使用其中 2–3 个功能色。
- **科学结构优先：** 两阶段均不得擅自改变 F11-A 已确认的节点、连接、关键公式和数据隔离规则。视觉设计可以充分重排，不应重新定义算法。

设计优先级：科学正确性 ＞ 核心方法表达 ＞ 结构简洁与留白 ＞ 整体视觉设计 ＞ 装饰性 SVG。

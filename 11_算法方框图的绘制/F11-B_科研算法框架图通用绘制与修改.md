# F11-B｜科研算法框架图通用绘制与修改 v2

> **定位**：第 11 类默认入口。适用于从零绘制论文算法机制图，或在已有 HTML/SVG 图上进行最小修改；强调信息取舍、真实数据流、浅色极简设计与可编辑输出。
>
> **经验来源**：从用户满意的 SAFE-Gait Fig.2 HTML/SVG 及 [F11-A 专项修图提示词](F11-A_SAFE-Gait_Fig2_%E6%9C%80%E5%B0%8F%E4%BF%AE%E6%94%B9%E4%B8%8E%E9%80%BB%E8%BE%91%E7%BA%A0%E6%AD%A3.md) 提炼**通用设计原则**，不是直接复制该项目的 CP/SB/DS/MCS 或 query 标签关系。尚未经过跨项目绘图质量 A/B 验证。

## 使用方式

把本 Prompt 与当前算法说明、论文方法部分或已有 HTML/SVG 一起提供给 AI。默认自动识别“新建 / 最小修改”；如需特别突出创新模块、改为纵向布局或导出其他格式，可直接附加明确要求。不需要每次填写表单，也不要求 Agent 重读整个科研工作流。

## 可直接复制的 Prompt

```text
请依据我提供的论文、算法说明、代码、科研记录或现有图，创建或修改一张 SCI 论文级算法方框图。优先做到**科学关系准确、核心机制直观、视觉简洁**，不要为了完整而把全部实现细节画进图中。

【任务模式】
- 已有满意的 HTML/SVG：默认“局部修改”，优先保留原布局、模块、配色、字体、公式与箭头；只改确有问题之处。不得借修错重画整图。若已有修改已满足要求，不重复添加。
- 没有现成图：采用“新建”，从可信材料提炼主要流程后设计。若用户指定其他模式、格式或风格，以用户要求为准。
- 算法机制图重点画输入→创新机制→输出及必要依赖；实验/评价流程图则重点画数据划分、实验分支、评价输入和隔离边界。不要把两类信息不加选择地塞进一张图。

【科学主旨压缩】
先用一句话概括本图要解释的创新，再确定必要的节点、分支和依赖。应合并不影响主旨的普通实现步骤，切忌把伪代码逐行画成框。

【内容取舍：简洁不是遗漏】
在内部按三层筛选，不输出冗长分析：
- P0 必画：主输入、核心贡献、主要输出，以及保证科学解释正确的真实依赖或数据隔离。
- P1 按需画：理解贡献不可缺少的子模块、方法差异、关键公式和支路。
- P2 默认不画：普通预处理、实现细节、超参数、重复计算、软件名、泛化说明及与图的目的无关的评价细节；可留给正文或图注。
优先约 5–7 个主要模块作为新图的设计起点，**非硬性上限**。能合并的同类步骤尽量合并；确有复杂机制时保留必要额外节点，不能牺牲正确性。每添加一个框、箭头或注释，都需有明确且不可由现有元素替代的阅读价值。

【逻辑约束】
- 只绘制有资料依据的模块、公式、先后顺序、数据流和依赖；不能凭经验编造算法细节、实验结果或因果关系。
- 根据实际方法区分训练、校准、推理和评价；仅在确实存在这些阶段时绘制。参数冻结、归一化、标签真值、验证/测试隔离等，只保留对理解或防止误解必需的依赖。
- 箭头必须对应真实关系：默认实线表示主要计算/数据流，虚线表示清晰标注的辅助依赖；同一张图中线型语义始终一致。不能把并行过程画成先后，也不能让评价真值流入不应使用它的预测/训练阶段。
- 缺失且影响逻辑正确性的资料明确标注“待核实”，不擅自补全；非关键细节不阻断作图。

【资产当前状态】
当前已批准 56 项：Robot Toast 16（MIT）、OpenMoji 4（CC BY-SA 4.0）、Lucide 12（ISC）、Tabler 12（MIT）、Phosphor Duotone 12（MIT）。SciSVG（D）未获选择，不得导入。Robot Toast 用于统一角色，通用小图标默认只选一套；OpenMoji 可少量强调。

【视觉模式与素材匹配】
- TECHNICAL：默认极简技术图，不强制配图。
- ILLUSTRATED：用户要求插画时才启用；读取 assets/manifest.json，按 concepts 与 style 选择 id，只打开实际选中的 .svg。Robot Toast 用于角色，Phosphor Duotone 可作为柔和辅助图标；TECHNICAL 首选 Lucide，复杂工程结构可用 Tabler。不要无理由混用多套通用图标。每模块至多一个、整图通常 0–4 个；绝不为了插图增加算法模块。
- 将 SVG 路径内联到最终图，离线可用且可编辑。无适合素材时不强行添加，也不导入未核实许可的第三方插图。

【视觉风格：克制、平面、留白】
- 纯白背景；简单矩形、细灰边框；低饱和度淡蓝/淡橙/淡绿作为少量语义分组色。同类模块配色一致。
- Arial/Helvetica 等清晰无衬线字体，字号层级克制；模块标题短，正文只留必需词句或公式。
- 优先从左到右的一条主线，少量上下分支与必要的父子模块；统一对齐、间距和箭头方向，保留留白。
- 避免复杂背景、渐变、阴影、3D、装饰图标、过多颜色、密集注释、重复标题、无意义图例以及过量箭头交叉。
- 排版拥挤时优先删减 P2、合并同类模块、调整间距，而不是一味缩小文字或无限放大画布。不得为了简洁删除 P0。

【技术输出与检查】
- **新建绘图**：默认交付可重复生成的源代码、独立可编辑 SVG 和离线自包含 HTML；画布可从 1600×900 起步并按实际内容调整。SVG 使用清晰的元素分组及一致的箭头标记。
- 已有 HTML 的局部修改仍遵循原要求的最小输出，不擅自另导出；PNG/PDF 只在明确要求时生成，不改无关 HTML/CSS 结构。
- 完成前定向检查：每条边的起点/终点/方向；训练/测试标签和模型依赖；数据泄漏或错误顺序；文本溢出、遮挡、箭头压字与模块对齐。具备浏览器/渲染工具时预览检查；没有工具则不声称视觉验证通过。
- 新建图交付源代码、SVG、HTML；已有图遵从原要求；无法编辑文件则输出完整可复制代码。只附必要的修改说明或未核实项，不输出内部设计过程，也不新增其他产物。
```

## 与 F11-A 的关系

- **F11-B（默认）**：从科学材料创建新图，或对任意项目的已有图进行必要修改。
- **[F11-A（专项历史案例）](F11-A_SAFE-Gait_Fig2_%E6%9C%80%E5%B0%8F%E4%BF%AE%E6%94%B9%E4%B8%8E%E9%80%BB%E8%BE%91%E7%BA%A0%E6%AD%A3.md)**：只针对 SAFE-Gait Fig.2 两条既定依赖的局部修复；原始限制保持不变。

判断质量时优先看逻辑/依赖正确、贡献是否清楚、缩放后的可读性和冗余程度；**模块越少并不天然越好**。

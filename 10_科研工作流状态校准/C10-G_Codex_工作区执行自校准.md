# C10-G｜Codex 工作区与科研执行自校准（v2）

> **用途**：Codex 在没有已知故障时，针对真实工作区、Git 差异、实验协议和有效 Run 做增量一致性核对。**只读自检不等于获准修复/训练；无问题不修改文件。**

## 可直接复制的 Prompt

```text
# C10-G｜Codex 工作区与科研执行自校准 v2

你是当前 PD-RW 科研项目的代码与实验执行 Agent。请在没有已知故障的情况下，主动核对工作区、任务状态、实验协议和执行证据，防止上下文丢失、代码漂移、重复实验、结果误用及错误任务延续。

**权威来源**
- PD-RW：https://github.com/phr-devil/Problem-Data-Research-Workflow
- PD-RW-Agent：https://github.com/phr-devil/PD-RW-Agent
- 当前项目适用的 AGENTS.md、Skill、原始用户授权、冻结协议、STATE/EVENTS、RESEARCH_RECORD 与真实 Run。

按需读取，不重复加载完整规则库。远程仓库版本不能直接证明本地规则或 Skill 已更新。

## 1. 恢复与定位

优先复用当前上下文及已核证据，确认：

- 正确的项目 root、分支、工作区与 Task/Claim；
- 已批准 H6/H8 范围、当前授权及保护边界；
- 数据、协议、代码版本和有效 Run；
- 当前未提交改动、已完成任务与未完成操作。

先识别已有用户改动及当前工作区差异，不覆盖、不清理、不擅自回滚。

若属于已登记项目的会话恢复，且相关 MCP 实际可用并获准使用，按 PD-RW-Agent Skill 优先调用一次 compact resume。不重复获取同一上下文。

MCP 不可用时记录一次原因，回退合法原始文件。未登记项目不得伪造身份或恢复记录。

## 2. 主动检查关键一致性

即使程序没有报错，也对当前任务的关键依赖进行增量核对：

**A. 任务与状态**
- 是否操作错误项目、错误分支或过期文件；
- 是否遗忘已完成工作、有效 Run、用户修改或原始作者决定；
- 是否将旧进程、缓存、摘要或诊断结果误认为当前执行状态。

**B. 代码与协议**
- 输入、输出、数据划分、独立单位及预测时点是否符合冻结协议；
- 是否出现数据泄漏、特征使用越界、指标口径改变或错误结果引用；
- 当前修改是否破坏原有功能、可信结果或必要科研不变量。

**C. 执行与证据**
- 拟执行任务是否已经完成或存在等价有效结果；
- 中断任务是否仍在运行，是否可能重复写入或覆盖结果；
- 代码测试通过是否被错误地等同于实验有效或科学主张成立；
- 下一步是否处于真实科研策略及操作许可范围。

只检查与本轮工作有关的项目文件、差异、配置、必要日志和有效证据。不默认执行全库扫描、全量审计或重训练。

## 3. 最小修复和定向验证

依据证据处理：

- 无实质问题：不修改任何文件，继续原任务。
- 明确且已授权的局部工程错误：最小范围修复，并运行针对性测试。
- 科研协议、数据真值或评价异常：先定位受影响的 Run/Claim，必要时调用已有审计工具，不擅自修改冻结协议或重解释结果。
- 证据不足：标记 UNKNOWN，执行最低成本合法核查。
- 状态不明的历史进程：先核对真实状态和输出，不盲目重启。

修复前确认相关文件的既有差异；修复后检查实际 diff、相关测试及保护边界。禁止通过删除测试、降低评价标准、修改真实标签或污染 SEALED 来制造 PASS。

优先复用既有可信结果。只有确有必要且已授权，才执行新的计算或训练。

## 4. 严守 Agent 的执行边界

- PD-RW 是科研规则唯一权威；现有 Agent Skill/MCP 只在其真实能力范围内使用。
- H6/H8 已生效且范围未变化时不重复审批；普通已授权 H7 工作允许连续自主实施。
- 数据下载、付费、SEALED、独立确认、绘图、正式写稿、外传、提交和发布等动作分别核对实际许可。
- 本次自校准不授予新的文件写入、数据访问、训练或外部操作权限。
- 不使用破坏性 Git 操作清理工作区，不自动覆盖用户代码、原始数据或有效科研记录。
- 不将 Agent MCP/CLI 的结构 PASS、SQLite receipt 或合成 Host 诊断当作真实科研验证。
- 不建立第二套科研账本；重要科学变化只在已有且获准修改的原始项目记录中增量维护。

当前任务仅授权检查时保持只读；只有原任务已授权相应修改或实验，才能实际执行纠偏与后续技术工作。

## 5. 继续执行与交付

自校准不是重新启动项目。修正必要偏差后，恢复当前最有价值的合法工作，不重复计划、实验或测试。

重要任务交付前核对实际修改、运行结果、证据引用与尚未解决的问题。

只输出：
1. 状态：一致 / 已纠偏 / 关键事项待核实；
2. 关键证据及实际修复内容；
3. 必要测试结果与剩余限制；
4. 已完成工作及下一合法行动。

无实质异常时简短报告，不生成新报告文件，不声称自检证明了整体科学正确性。

**原则：保护现有工作、验证真实差异、最小合法修复、避免重复执行、保持科研连续性。**
```

## 与其他指令的关系

- 会话中断需要真实恢复时优先 C10-A；发现明确工程/科研异常时使用 C10-B。
- 对受保护动作的权限核验仍以 PD-RW 和真实宿主授权为准，C10-C 可按需检查。
- 仅在正常执行的关键交付或重大工作区变化时使用 C10-G；不与 C10-F 或 C10-A～E 连发，不替代 PD-RW-Agent Skill/MCP。

**验证边界**：指令不会自行安装 Skill/MCP、恢复不存在的科研 Run 或建立 SEALED 隔离；实际 Codex 效果与 Token 收益仍为 NOT_MEASURED。

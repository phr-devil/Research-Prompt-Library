# 10｜PD-RW-Agent 科研启动、恢复与状态校准指令

> **定位**：面向 WorkBuddy + PD-RW-Agent 的七种按需指令（C10-A～G），用于启动、接续、偏差校准、权限检查和科研价值判断；不是新的科研流程、审批机制或常驻记忆系统。科研规则以 [PD-RW](https://github.com/phr-devil/Problem-Data-Research-Workflow) 为准，工具能力以当前已安装的 [PD-RW-Agent Skill/MCP](https://github.com/phr-devil/PD-RW-Agent) 为准；提示词不替代原始用户授权。

## 选择入口

| 编号 | 场景 | 何时使用 | 结果 |
|---|---|---|---|
| **C10-A** | Agent 状态恢复与自主接续 | 新会话、任务中断、混淆项目或阶段 | 可靠恢复并继续合法任务 |
| **C10-B** | Agent 执行偏差校准 | 发现规则遗漏、证据冲突或重要交付偏差 | 定向纠偏，必要时直接恢复研究 |
| **C10-C** | Agent 关键权限检查 | 真正涉及作者核心选择、SEALED、写稿、外传或付费 | 只拦截缺失授权的受影响操作 |
| **C10-D** | Agent 科研价值与历史经验复用 | 显著负结果、重复无增量、重要研究方向选择 | 基于原始证据比较继续、补证、收窄与转向 |
| **[C10-E](C10-E_全新科研项目启动.md)** | 全新科研项目启动 | 新方向首次建立，尚未形成真实注册项目 | 保留七项配置与 H1–H6 作者选择，之后接入 Agent |
| **[C10-F](C10-F_ChatGPT_科研上下文自校准.md)** | ChatGPT 科研连续性与主动自校准 | 无明显错误，但担心上下文遗忘、决策漂移或下一步建议失准 | 只读核对可信状态锚点；无异常直接继续 |
| **[C10-G](C10-G_Codex_工作区执行自校准.md)** | Codex 工作区与执行自校准 | 无明显故障，重要交付或工作区变化后需要一致性核对 | 增量检查代码/协议/Run/差异；在原授权内最小修复 |

**只选一条与当前任务匹配的提示词。** E 用于新项目，A 用于正式恢复已存在项目，B/C/D 按异常、权限或科研价值问题触发；F/G 用于**尚未发现明确错误**时的轻量主动校准（ChatGPT/Codex 分工）。按需调用，不将 A～G 连发，也不固定每 N 轮重复检查；已有上下文和可信证据优先复用。

## 执行端与证据边界

- **WorkBuddy（默认）**：只有在本会话实际连接、已获准调用相应 MCP 时，才调用工具并报告真实工具名与结果。对真实登记的现有项目，C10-A 优先一次 `get_resume_context(project_id, detail_level="compact")`；不无故再调 `get_project_context` 或重复通读全库。MCP 不可用时写明 `MCP_NOT_USED` 及原因，一次性回退合法原始文件，不循环重试。
- **ChatGPT（外部复核）**：只能依据当前对话可访问的文件、链接与工具独立分析；在 ChatGPT 输入 Prompt **不会自动触发另一个 WorkBuddy 对话**、本地 MCP、代码修改或实验。不能声称本地检查已执行；需要实际操作时把指令传给目标执行环境。
- **规则与授权**：PD-RW 的权威规则、作者原始选择、冻结协议和真实 Run 优先。状态标记、案例索引、Agent 自评、SQLite receipt、工具可见性或 `next_action_hint` 均不是操作授权；UNKNOWN 不等于 PASS、FAIL 或必须新增审批。已授权的安全普通 DEV 可连续执行；缺少关键许可时只暂停受影响操作。
- **科研记录**：优先现有 `STATE`/`EVENTS`、`RESEARCH_RECORD.md`、`PAPER_BLUEPRINT.md` 与原始 Run；不建第二套科研账本，不把诊断或合成 Host 结果当成真实科研证据。只有在重要变化时按原工作流更新记录。

## C10-A｜Agent 状态恢复与自主接续

适用：新会话、中断或项目状态混乱。**可直接复制**：

```text
请按当前 PD-RW-Agent Skill 恢复并继续本科研项目。优先复用已知项目身份、规则版本和原始证据；若当前执行端已连接且获准使用 MCP，对真实登记的项目调用一次 get_resume_context(project_id, detail_level="compact")，不重复调用项目上下文工具。MCP 不可用时通过合法原始文件回退并报告 MCP_NOT_USED 与原因，不假称调用成功。

核实当前 Task/Claim、有效 Run、未完成操作、原始作者选择和关键证据缺口。区分科研状态与旧进程状态，不将历史任务不可盲目重启误当作全项目禁止工作；辅助状态与下一行动提示均不授予新权限。

在既有授权范围直接继续最有价值的合法 DEV 或只读研究，不重复已完成实验；只有关键科研选择、必需证据或真实权限缺失时暂停受影响操作。简报恢复结论、依据、阻断事项和已执行/下一合法行动。
```

## C10-B｜Agent 执行偏差校准

适用：实际发现重要偏差时使用；不是每轮固定审查。**可直接复制**：

```text
请依据当前 PD-RW-Agent Skill 和 PD-RW 权威规则，定向检查本任务是否有可验证的执行偏差。复用已核实的状态、规则、Run 和授权，只读取与异常相关的证据；必要时按需使用 audit_project_state、reconstruct_project_history、verify_run_evidence 或 audit_scientific_experiment，不重复全面恢复、全量审计或无效实验。

核对阶段偏离、规则遗漏、错误结论、重复实验及 RESEARCH_RECORD/PAPER_BLUEPRINT 是否需要因实质变化更新。发现确凿偏差，在已有权限内修正并继续；无实质问题就直接继续原任务。不新增审查阶段、审批或平行文档，不把结构 PASS/MCP 状态当作科学正确性证明。

仅报告实际偏差、证据、修正和下一合法行动；未执行的工具调用与未核查证据明确标注。
```

## C10-C｜Agent 关键门禁检查

适用：仅在操作真正触及受保护门禁时使用，普通安全 DEV 无需重复确认。**可直接复制**：

```text
请按 PD-RW 当前权威规则，核对本次具体操作的真实科研与执行权限。只检查当前涉及的作者核心 Task/Claim、原始 DEV 授权、数据下载、SEALED/正式确认、写作、绘图、付费、外传或投稿等门禁，不无故扩大到其他阶段。

以原始用户消息、冻结协议和实际宿主能力为准；STATE、MCP receipt、预检、工具可见性和 Agent 自评不能独立证明授权。已批准范围内的普通安全 DEV 自主继续；确实缺少关键许可时只阻止受影响操作，其他独立合法任务照常推进。

简报门禁结论、核验来源、被限制的操作及下一合法行动。本次检查本身不授予新权限。
```

## C10-D｜Agent 科研价值与历史经验复用（可选）

适用：有重要负结果、持续无增量或重大投入选择时使用。**可直接复制**：

```text
请基于当前 PD-RW 与可信原始证据，评估本项目下一项最有科研价值的行动。优先复用有效 Run、具名最近邻文献与已冻结的研究判断；必要时调用 search_research_memory 检索历史成功/失败案例，再按需调用 review_lesson_applicability、review_evidenced_lesson 等核实适用条件。案例索引、关键词相似和旧负结果不能自动证明机制相同或直接宣告 STOP。

核查核心科学增量、强基线、最强反解释、证据缺口、资源成本及合规投稿潜力。对比继续、补充决定性证据、收窄、横向转向或结束当前分支，推荐一项并说明关键反证条件。普通已授权 DEV 可自主继续；实质更改核心 Task/Claim 或项目级重大战略必须遵守作者选择门禁。

避免重复研究已证伪的同一前提，也不因一次负 Pilot 否定整个项目。只报告关键证据、建议、未知事项与下一合法行动。
```

## C10-E｜全新科研项目启动（独立文件）

使用 [C10-E_全新科研项目启动.md](C10-E_全新科研项目启动.md)；保留研究方向、十类研发目标、贡献偏好、数据/算力（Windows 11、RTX 4080 16 GB）、周期与其他限制的用户配置。新项目尚未完成真实身份/目录/私有映射登记时，不可伪造现有项目身份来调用恢复工具。H1–H6 战略选择遵从 PD-RW，登记后再转 Agent 常规接续；不要在 C10-E 与 C10-A 之间机械往返。

## C10-F / C10-G｜无异常时的主动自校准（独立文件）

- [C10-F｜ChatGPT 科研连续性与主动自校准](C10-F_ChatGPT_科研上下文自校准.md)：核原始用户决定、Task/Claim、有效 Run、授权与下一行动之间是否一致；只访问 ChatGPT 实际可用的来源，不冒充执行端。
- [C10-G｜Codex 工作区与科研执行自校准](C10-G_Codex_工作区执行自校准.md)：核真实工作区、未提交改动、实验协议和有效证据；检查本身不授予文件写入/训练权限，不对正常项目制造修复任务。

**触发边界**：长对话后的关键科研决策可用 F；代码变更后的重要交付可用 G。真正中断恢复优先 A，已知错误优先 B；不叠加执行、不要求每轮自检。两者均不创建持久记忆、平行科研账本、额外审批或工具级安全门禁。

**交付原则**：一次输出一份主要结果、可核验证据、已执行工具和下一合法行动；不堆叠日志、反复请求普通 DEV 审批或虚构 WorkBuddy 已完成的执行。提示词的真实效用与 Token 收益需要实际 A/B 验证，当前不声称已测得改善。

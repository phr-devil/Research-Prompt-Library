# C10-E｜PD-RW 全新科研项目启动（使用者配置版）

> **用途**：新建科研项目时一次性复制本 Prompt，先由使用者填写研究偏好，再按 PD-RW 真实作者决策推进 H1–H10。与本目录 C10-A–D 的中途状态校准用途不同：**E 是新项目启动，不是恢复旧项目**。科研权威规则始终以 [PD-RW](https://github.com/phr-devil/Problem-Data-Research-Workflow) 的最新可核实文件为准；本文件不复制、不改写其规则合同。未经权限验证，不默认可以下载、训练、访问 SEALED、绘图或写稿。

## 使用说明

1. 复制下面完整的 `text` 块；**只需修改第一部分**，在 `[ ]` 中选择（改成 `[x]`）或填写自定义内容。研究方向允许多选，研发目标选择一个主目标；其余可按需要多选。
2. 如果某项不确定，保留 `未指定`；AI 应解释可行选项并给出首选，不应把空白自动填成已获作者批准。
3. 本 Prompt 不替代 H1–H6 选择、正式科研授权或实验协议；首次回应应依据已填配置开展合法只读预审，并指出当前真正需要作者选择的节点。
4. 既有项目请使用 C10-A 等恢复与校准提示词，不要用本模板重新初始化已有项目。

```text
================================
第二部分：PD-RW 规则识别与科研执行
================================

1. 规则识别与初始化
- 以 AGENTS.md 为入口、WORKFLOW.md 为科研总控，按需加载当前任务专题；不通读全部仓库，不把本 Prompt 当成规则的第二权威。
- 核实可访问的 Git 版本与当前规则，识别三循环、六活动、H1–H10、C01–C12、R1–R6、P1–P5 及权限／独立确认／写作门禁。
- 不能验证版本时记 RULE_VERSION_UNVERIFIED；区分已读文件、已有证据、推测与未知。
- 这是新项目；不得继承旧项目的 Task、数据使用许可、SEALED 权限、科研成功结论或用户授权。

2. 使用者配置识别（H1–H2）
- 把第一部分映射至研究范围、研发目标、科学贡献倾向、证据资源、计算条件、周期和风险边界。
- 已明确的选择直接复用；未选择的保持待定。只有实质性关键缺口才向作者提出一次有依据的推荐与备选，不使用冗长问卷反复收集已知信息。
- “快速发文”不等于低质量或刷分，“顶级突破”不等于默认堆砌神经网络。

3. H1–H5 科学问题搜索与作者选择
- H1：确认研究范围、目标与资源边界。
- H2：比较六类问题来源及五类竞争力偏好，结合配置提出推荐。
- H3：按 BREADTH_SCAN → DEEP_FALSIFICATION → COMPETING_CHOICE 搜索候选科学问题；核最强具名近邻、独立知识差额、核心反证及资源成本。不能以“没有检索到”证明原创。
- H4：根据官方元信息比较数据集、独立单位、真值、许可、容量与验证可行性；理论／仿真按适用 PROOF_PATH。选择数据不授权下载。
- H5：基于问题、数据证据与竞争性反证，给出最有依据的最终科学问题首选和通常 1–2 个不同失败前提备选，由作者选择或明确范围委托。
- 一条真实用户消息可以同时覆盖多个节点，不机械逐轮确认；待决时继续允许的不依赖该选择的只读工作。

4. H6 核心科研 Task／策略选择
- 依 AUTHOR_STRATEGY_REVIEW.md 与 CONTRIBUTION_TAXONOMY.md 比较 C01–C12、R1–R6、P1–P5 的合理组合，推荐核心 Task。
- 每个候选说明：科学问题、主要贡献、具名近邻差额、独立新知识、关键可否证实验、数据与公平评价条件、成本／速度、失败前提与备选路径。
- AI 明确首选，通常附 1–2 个不同战略选项；作者可选择主方案、主辅组合、有限委托或暂缓。必须记录真实原消息与选择范围；AI 自荐不能视为 H6 批准。

5. H7 连续自主研发
- H5/H6 真实有效且本地合法 DEV 资源和操作权限具备后，AI 自主开展合理规模的算法／理论设计、代码开发、强基线、训练、调参、消融、错误分析、机制诊断、负结果处理和必要补证。
- 普通安全非付费本地 DEV 不逐次请求作者批准；复用可靠 Run、固定评价单位和协议，禁止数据泄漏、事后挑选、无信息重复训练及人为弱化基线。
- 算法并非必需时可选择机制分析、评价纠错、理论或系统路线；H7 新算法分支按适用性处理，不强行发明新网络。

6. H8 科学贡献与重大升级
- 持续回收真实正负结果，区分科学发现、算法性能、混杂及测量伪影，比较相对具名近邻的独立贡献。
- 只有需要冻结／实质改变主 Claim、改变主贡献类别或重大研究战略时，AI 给出 KEEP / UPGRADE / NARROW / REFRAME / HOLD 的有依据首选与备选，比较验证缺口、资源成本、最强反解释和 Q2/Q1 潜力；由作者选择或有限委托。
- 次要 DEV 发现、普通模型修改和补证不反复触发 H8；不能凭 Agent 自评将候选结果认证为已确认。

7. H9–H10 独立确认与成果审查
- H9：依独立确认合同冻结 Claim、方法和评价协议，保护 SEALED／正式验证集；独立确认另需实际合法授权。
- H10：汇总科学任务、有效及负向 Run、独立验证、核心贡献、局限与投稿主张边界，提交作者审查。
- 不因完成 H10、获得 Q2 潜力或建立蓝图就自动开始正式论文写作；遵守 WRITING_GATE.md 的科研总结审查与独立正文授权条件。

8. 贯穿全过程的记录、权限和 Token 效率
- 按重要变化增量维护 RESEARCH_RECORD.md 和 PAPER_BLUEPRINT.md，不制造第三份重复科研账本。
- 作者的 H1–H6/H8/H9/H10 科学选择、AI 的 H7 技术自主，以及新库下载、SEALED、付费、外传、实际绘图、正式写作和投稿分别判断，不能相互授权。
- 主机执行器和文件权限需要真实执行约束；任何检查器 PASS、文件标记或 Agent 口头声称都不能替代原始用户消息与真实科学证据。
- 复用已验证资料与现有 Run；仅检查适用规则、关键依赖和受影响测试，减少重复读取与无意义多 Agent 调用，不牺牲科学正确性。

9. 立即启动（本轮输出）
- 先核当前可访问 PD-RW 规则与第一部分配置，把已决定／未决定的 H1 条件列清楚。
- 在当前真实授权范围内开展必要的公开文献和科研机会初步搜索，并按研发目标排序，给出一个明确首选及可信备选、具名近邻、主要风险与关键未知。
- 标明当前 H 节点、已有证据、作者需要选择什么、下一合法行动。不要因为模板默认项自行冻结最终科学问题，不越权下载、训练、SEALED、绘图或写稿。
- 输出高信息密度、简洁；不重复已完成工作，不以状态自评冒充执行成功。
```

## 与本目录其他 Prompt 的关系

- **C10-E（本文件）**：启动**全新**科研项目，使用者先填写研究偏好与研发目标，再按 PD-RW 逐步选择。
- **C10-A**：恢复**已有**项目的有效历史、原始授权和下一步。
- **C10-B/C10-C**：在已有任务中检查实际执行偏离或关键权限。
- **C10-D**：已有可信结果但科学价值或继续投入存在疑问时复核。

如 PD-RW 将来变更 H6/H8 等权威决策合同，以最新可验证工作流为准，更新本文件的调用示例即可；不在 Prompt Library 另设一套科研审批系统。

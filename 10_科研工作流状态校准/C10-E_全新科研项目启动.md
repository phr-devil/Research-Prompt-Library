# C10-E｜PD-RW × PD-RW-Agent 全新科研项目启动（使用者配置版）

> **用途**：全新科研项目的“科学选题 → 作者决策 → 真实项目登记 → Agent 接续”入口。**PD-RW** 是唯一科研规则来源；**PD-RW-Agent** 负责 WorkBuddy 的 Skill 路由、状态恢复、原始 Run 证据检索与有限审计，**不是**另一套工作流，也**不是**自动获得执行许可的工具。此文件不重新定义 H1–H10 或权限合同。
>
> **适配基线（核查于 2026-11-14）**：PD-RW v1.13；PD-RW-Agent v0.7.7 (H6 方案选择 PR 版本；执行端以实际安装版本为准)。执行时以当前可核实仓库 commit、实际安装的 Skill/MCP 和原始项目证据为准；版本不符不假称已升级。Agent 的真实 WorkBuddy 收益与 Token 节省仍为 `NOT_MEASURED`。

## 使用说明

1. 复制下面完整代码块，**只填写第一部分**。研究方向、贡献偏好可多选；研发目标选一项主目标。空白保持未指定，不等于默认项已由作者选择。
2. 第一部分就是研究目标与资源的用户配置，不再重复询问 H1/H2。Agent 先自主完成 H3–H5 候选调查，只在展示具体研究方案后要求一次 H6 明确选择；不因普通 DEV 实验反复授权。
3. **全新项目不等于已登记项目**：在项目目录、身份与私有映射真实建立前，不能直接套用“恢复现有项目”的 MCP 调用；无法接入 Agent 仍可按 PD-RW 合法只读开展选题。
4. 若发现真实旧项目，请停止“新建”路线，转 PD-RW-Agent 的 [项目恢复 Skill](https://github.com/phr-devil/PD-RW-Agent/blob/main/skills/pd-rw-research/SKILL.md) 核对原有状态，避免重建和覆盖。

```text
第二部分：Agent 接入与科研执行

【A. 启动与真实能力识别】
- 本 Prompt 仅传递用户科研配置；PD-RW 是 H1–H10、科研证据与权限的唯一权威。仅按当前任务读取 AGENTS.md、WORKFLOW.md 及相关一份规则，记录可核实版本与缺失项；不复制整套规则或重复审查。
- 核对当前是否已有相同项目的真实 root、STATE、RESEARCH_RECORD、Run 和作者选择。项目 ID 不能单独证明项目身份；发现旧项目即停止新建，改用 C10-A/Skill 恢复，不覆盖原始资产。
- 只以实际 WorkBuddy 环境判断 Skill/MCP 是否可用；不得凭 GitHub README 推断已连接。未连接注明 MCP_NOT_USED 和原因，回退合法文件只读流程，不循环重试。**未登记项目不得调用需要 project_id 的 get_resume_context、get_project_context 或项目审查工具，也不得伪造登记。** 可用时只按需检索规则或历史案例。

【B. 从启动配置到一次 H6 方案选择】
- 用第一部分真实勾选形成 USER_SCOPE (H1/H2)；已填写的目标、方向、资源、偏好不再提问。未填或仅标注“默认”保持 UNKNOWN，不能冒充作者已选择。

- H4/H5 由 AI 先完成官方元数据与问题—证据适配调查，形成 PROPOSED 候选；不要求用户分别答复 H3/H4/H5。Agent 汇总 1 个首选及必要备选、具名最近邻、关键反证、独立证据、资源成本与预期贡献，展示单张 H6 科研方案卡后**停止依赖该方案的新主线研发**，只接受用户针对当前方案的具体选择或明确的有限委托（不能把泛泛“继续”当作选择）。一次用户回复同时确定所选 H3–H6 内容，并保留真实原消息引用。选定数据仍不是下载授权。**科研战略选择不等于下载、训练、SEALED、写作或其他操作许可。**

【C. 从选题到真实项目登记】
- 只在项目 root/稳定身份真实确定且取得相应文件创建/修改许可后，依 PD-RW 维护必要 STATE、EVENTS、RESEARCH_RECORD 和适时 PAPER_BLUEPRINT；不制造 Run、审批或 SEALED 证据。
- PD-RW-Agent MCP 不负责创建/注册科研项目。由有权限的 WorkBuddy/操作者维护私有 project-map.local.json，核对映射路径与原始科研身份；禁止将私有映射提交 GitHub，也不得把映射或 SQLite receipt 当作科研证据。
- **登记并核验后**，已有项目在新会话/中断时用一次 get_resume_context(project_id, detail_level="compact") 接续；仅定位才用 get_project_context。工具不可用时合法回退，不因 MCP 异常阻断其他独立合法行动。

【D. 已授权研究的自主推进】
- 当 H5/H6 作者选择和具体 DEV 数据、操作范围均真实满足时，由 WorkBuddy 已获准的宿主工具连续执行范围内安全的 CPU/GPU DEV 编码、调参与决定性实验，不为普通技术迭代反复确认。**当前 PD-RW-Agent MCP 不执行真实 DEV/GPU、不会自动写科研 Run、不能证明作者授权或隔离 SEALED**。
- 优先复用有效 Champion/Run；发现证据冲突或重复风险，才按需使用 find_experiment_evidence、check_duplicate_experiment、verify_run_evidence、audit_scientific_experiment 等。历史失败由 search_research_memory 提供索引，必要时经适用性/原始 Run 审查，不能凭相似案例自动 STOP。
- 区分 INVALID、UNDERTRAINED、COMPARABLE_NEG、INCONCLUSIVE 与 UNKNOWN，停止没有信息增量的分支但不把一次负 Pilot 等同项目失败；可在合法范围内先修复、补证、收窄或探索不同机制。H8 的实质主 Claim/战略变化、H9 独立确认与 SEALED、H10 正式成果由原 PD-RW 门禁处理。

【E. 科研证据、门禁与交付】
- 科研事实只写入原项目的 STATE/Run/EVENTS、RESEARCH_RECORD 和按需维护的 PAPER_BLUEPRINT；操作 receipt/Host 合成诊断不是科学证据。新数据下载、付费、外传、重大改题、正式确认、绘图、正文写作及投稿，须分别具备实际原始授权；作者选题不能替代。
- 交付一份主要结果，附项目/规则身份、关键已核证据、未核实项、真实工具调用、已完成行动和下一合法行动。不无故添加平行文档、重复审查或堆叠日志；未运行的实验标 NOT_RUN。

【F. 本轮立即行动】
1. 核对已填写配置、最少必要权威规则及真实 Agent 可用性，首先排除“旧项目被误当新项目”。
2. 在当前合法只读范围比较科学机会和最近邻，给出一个首选及必要备选、最强反解释和下一决定性证据。
3. 只提出一次当前具体 H6 科研方案作者选择；之前的 H3–H5 草案由 Agent 内部完成，不重复要求填写 H1/H2。未经相应授权不新下载、不训练、不登记，不因其他门禁缺失停止独立合法研究。
4. 精炼交付：首选与依据｜备选和失败条件｜证据/UNKNOWN｜作者节点｜下一合法行动；不得声称未发生的 MCP 调用或实验。
```

## 与其他提示词的关系

- **C10-E（本文件）**：从新方向启动到“真实项目 + 私有注册 + Agent 接续”的桥接；不是恢复现有项目。
- **已有项目的恢复/偏差校准**：使用当前 PD-RW-Agent Skill 和 PD-RW 原始规则；不把本新项目模板当作恢复指令。
- **Agent v0.7.5 的 `pd-rw-research` Skill**：主要为已登记项目服务；本 Prompt 只负责正确进入那条路径，不用大段重复它的内部实现。

**权威性**：科研决策、H1–H10、DEV/SEALED 和写作门禁以当前可核实 PD-RW 为准；Agent 实际 API、可见工具及能力边界以当前已安装的 PD-RW-Agent 为准。遇更新按需适配，不为提示词另造审批或科研状态机。

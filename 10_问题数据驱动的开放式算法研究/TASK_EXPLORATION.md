# 活动 03、05｜从开放观察产生具体科研任务，并逐渐收敛

**目的**：允许具体科研任务在真实实验中形成，而不是在初选时假定一个新模型必定有效。第十章允许多任务探索，但不能无限“挑最好看的指标”；每个具体任务必须有**独立研究价值、可检验性与真实数据适配**的解释。

## 1. 四种可信任务来源

1. **真实失效/残差**：从合法开发集的跨设备、跨受试者、跨环境或长时间漂移中发现可复现失效；查看基线与数据是否匹配，事后切片只当探索。
2. **科学/物理先验**：已知材料响应、摩擦力学、接触时序、信号叠加、噪声模型等能否预测某种现象；未实测写 HYPOTHESIZED。
3. **应用能力缺口**：现有系统在部署前可用信息、延迟、稀疏标定、能源、故障预警或新设备适应方面仍有真实约束；不把离线分类分数替代实际闭环表现。
4. **具名近邻未解决部分**：对至少一项直接相关工作定位其适用条件、剩余失效域、成本或证据限制。部分重合正常；方法改名/换 Backbone 不构成独立贡献。

## 2. 从问题→任务候选：先产生，再小成本辨别

不要求一次凑满3条任务；可以只有一个值得探索的任务，或暂无任务继续合法数据观察。每张 TASK_CARD 最多 8 个字段：

- TASK_ID / ORIGIN：该任务出自哪个真实开发观察/论文/物理假说；OBSERVED / HYPOTHESIZED
- SCIENTIFIC_QUESTION：明确需要解释、预测或改善什么；不能只写“用 Transformer 提分”
- INPUT_TARGET：推理时可见输入、独立真值或理论证明义务；时序与组别
- TESTABLE_DIFFERENCE：哪种现象/实验结果能够区分该问题的不同解释（只有机制归因任务才必须写因果 A/B 预测）
- BASELINE：最简合法参照或已有有效 Run，未运行写 BASELINE_PENDING
- VALUE：成功后相较具名近邻可新增的独立知识、性能/资源/泛化价值（未证标 VALUE_UNVERIFIED）
- MINIMUM_PROBE：最低成本、最有判别力的合法开发集实验/观察（无需昂贵网络）
- COST_RISK：实际总 GPU/Token/人工/数据成本估计及一个最大不确定性；资源未批写 WAITING_FOR_AUTH

**筛选只用定性优先级，不造成功率**： (a) 真值/评价可达，(b) 可观察问题明确，(c) 合理的独立增量机会，(d) 下一个廉价实验的信息价值和总成本，(e) 已有资产复用程度。不需要初选时达到完整强基线、SESOI/MDE、全篇查新；只有已证实的不可替代科学/安全阻断才能阻止相应动作。高潜力尚未实测可低成本探索。

## 3. 任务组合与独立性：防止“搜索任务即论文成立”

- 同一个开发集可探索不同任务，但必须保存**候选清单、选择理由、试验顺序和失败/无增益结果**；不能只保留最好的一个。开发集的多个切片不是多个独立的研究结论。
- 一旦选中当前主任务，明确固定任务标签、主指标、合法组别、开发/确认边界和关键科学假说。允许后续改变，但必须版本化为新 task_id/claim_id，旧证据不自动转为新任务证据。
- 跨任务比较不能只按 F1/AUROC 数值排序；目标、分母、组别、成本及部署信息不一致时不可直接比较。优先判断“哪项任务有清楚、可独立证明的贡献”。
- 若开发集规模有限、原始任务已用尽可用确认数据，必须寻找新的独立组/数据库/外部验证或缩窄为探索性主张；**换随机种子、重新拆分已被反复择模的测试数据不产生独立确认**。

## 4. 四种研发机制（发现任务之后再考虑）

针对一个有价值的 TASK，可按证据按需比较以下解释，不要求所有任务都设新模块：
- **额外合法信息**：标定样本、历史窗口、其他合法传感器是否提供预测前可用的增量？
- **同输入归纳偏置**：物理先验、不变性、相对表示、跨域结构是否帮助泛化？先和简单容量匹配方法比。
- **训练/优化机制**：优化失败、数据不均衡、损失定义或训练预算是否主导表现？先做公平优化对照。
- **容量/工程能力**：模型容量、时间同步、数据读取与评价链是否制约结果？工程恢复不是科学提分。

机制实验负结果仅能排除其实际测试的范围；一次实验无显著增益不证明所有新机制不可能。应优先查真实训练收敛、可信正控和是否存在利用该信号的部署可行策略。

## 5. 逐步收敛为科学 Claim（不必一开始写论文）

**触发**：首次可信任务增量、连续有价值观察、发现可重复新科学现象，或准备增加资源/正式对外主张。不强制每次 Pilot 审核全文创新。

每个 CLAIM_CANDIDATE 包含：
1. **一句话研究贡献**：回答具体问题，不写“首次提出框架”而无证据。
2. **当前有效证据**：来自哪些 Run、独立组/开发集/评价器版本，原始预测和代码在哪里。
3. **具名近邻及简单解释**：强基线、简单优化或容量是否已经解释结果；证据不够则记 CLAIM_WITH_GAPS。
4. **最低确认需求**：冻结什么任务/协议/算法，哪组数据仍未参与选择，哪些统计/外部条件才能证实。
5. **备选主张边界**：无部署真值只说离线，只有代理只说代理；无独立增量记 NO_INDEPENDENT_CLAIM。

**任务选择建议**：优先一个可独立验证、有真实价值的主 Claim，其余保留为候选/负结果，不必同时做成多篇论文。第十章的科研成果可能是可靠的任务定义、物理现象、表示或算法机制；但“容易跑通”和“有论文主张”必须分开。

## 6. 三层止损：Run/机制 → Task → Area-Data

- **Run/机制 DISCARD**：该机制在公平前提下未表现价值，或修复代价过高；保留 BEST_VALID_RUN 与原始失败记录。还可在同 Task 下尝试不同的合理方法。
- **Task HOLD/PIVOT**：当前任务无法获得独立证据、没有剩余增量或继续探索价值过低；可在已批准问题—数据范围内选择有不同科学问题的任务，不要求每次用户重新选择算法名称。若实质改变用户选定的研究问题，应由用户确认。
- **Area-Data PIVOT/STOP**：多个任务共享的真值/观测前提被证伪、核心数据不适配且无合理修复路径，或研究总成本失衡；更换核心数据和研究方向由用户决定，不因单个 Task 失败自动触发。

# 活动 06｜开放探索之后的严格科学确认

**定位**：前面五项允许研究任务与算法机制逐步形成；进入论文主张时，不降低真值、分组、基线、独立确认、统计和创新贡献的标准。只在确实存在候选成果或拟公开论断时使用；工程 PASS/内部代理改善不自动进入论文阶段。

## 1. 先收敛 Claim，再确认

在读取任何封存确认内容前，应明确记录：
- CLAIM_ID、目标/单位/时间跨度、部署前可见输入、独立标签/证明义务、泛化对象（受试者/设备/环境/时间/机器人平台）。
- 本轮主指标/分母/分组、模型选择与调参历史、开发集数据切片搜索史；已完成的多个任务不应只报告“幸运最佳”。
- 固定拟验证的代码/模型 checkpoint、数据/划分/评价器版本，及训练和评价许可。
- 具名最近邻、至少一个合理简单基线与可解释替代；如证明机制的因果/归因，需有真正区分的负对照、消融和预测，而不是性能好就说机制成立。
- 预先定义想证实的效应/最小科学价值或可证伪理论结果；具体任务才确定相应合适统计方法与必要独立样本量。不强制每种科研问题都使用分类指标。

## 2. 独立确认与避免任务搜索偏差

- **封存holdout**：从早期任务发现、切片/标签观察、特征工程、调参和候选任务选择中隔离；仅在提前决定确认方案且确有权限时用于独立最终评价。若已使用确认集选择任务/模型，标 CONTAMINATED，不得事后换 seed / 简单重划分称为独立确认。
- **同一个公开数据库**也可能提供有效确认数据，前提是真正从未用于选择且与主张对应，分组和时间因果有效；外部数据库/新采数据可加强外部泛化证据，不能因为是同一个源就必然全无确认价值。
- **开放式多任务搜索**额外产生选择偏差。报告候选任务、切片、指标及开发集试验范围；对最终主 Claim 核对 **task_id、protocol_id、eligible_holdout** 的对应关系。原先为另一个任务预留的组，若标签、分组或时间结构不支持新主张，就不合格。只用独立于任务选择且真正适配该主张的数据/组验证最终冻结的方法；如没有，明确 CONFIRMATION_UNAVAILABLE，并限制论文/性能/泛化主张。
- 禁止确认集的重复“试到好”为止、测试结果驱动重新发明主张再复测同一集。**确认集出现失败/异质性也是合法结果，必须报告**；不能只展示成功的组、seed 或任务。真正的新假说可以继续探索，但需要新的独立确认路径。

## 3. 对应主张选择相应证据

| 主张类型 | 必须与之匹配的证据 | 常见越界 |
|---|---|---|
| 纯任务预测改进 | 同输入/组别/目标/分母的公平基线、样本/组级效应及区间、未污染确认 | 只比未调参旧基线、选择最好 seed |
| 跨设备/人/环境泛化 | 对应设备/人/场景或时间独立分组，协议版本与失效域 | 帧级随机切分冒充跨人泛化 |
| 少样本/在线适应 | K-shot、可用标定标签的时间因果与部署可行性、同条件公平调优 | 在测试目标上偷偷调参 |
| 机制与物理解释 | 竞争解释、必要消融/负对照/模型简化、独立现象 | Oracle优势冒充可学习机制 |
| 可靠性、失败预警 | 真实标签、预警提前量、选择/拒绝成本或校准质量 | 用预测置信度自身冒充独立真值 |
| 具身控制/机器人任务收益 | 实际闭环/反事实可识别性证据或清楚的合法代理范围 | 离线分数直接叫操作成功率 |
| 理论/新任务定义 | 可审核的证明/清晰可重复任务合同、对现有定义的真实增量 | 把新术语或重新整理数据当原创机制 |

## 3.5 从探索结果收敛论文价值（不按最优开发分数选故事）

为首选 `CLAIM_CANDIDATE` 只写一条最小证据链：**真实问题与独立价值 → 最近邻尚未解决的差额 → 最简单竞争解释 → 能决定主张的实验/图表 → 仍封存的确认资源**。不是预先编造正结果图；机制收益不稳定时，可以在证据许可下收窄为可重复的失效规律、轻量校准边界或新任务定义，但不能将常规工程复现自动包装为创新论文。多个 TASK/切片/指标的选择历史须披露；新 Claim 必须具备独立任务价值而非单纯改名。

**论文出口是分级证据，不是成功保证**：`NO_INDEPENDENT_CLAIM`（只有工程或已知基线）、`CLAIM_WITH_GAPS`（潜在新增贡献但核心证据未齐）、`DRAFTABLE`（可写明确局限的研究稿）、`SUBMISSION_CANDIDATE`（仍须作者核验及投稿选择）。只有强基线与独立确认支持的部分能写作已证实结果。论文目标期刊/影响因子不能代替科学评价，也不能反过来强迫探索期达到确认标准。

## 4. 公平与统计

- 基线包括简单可信替代及具名最近邻；合理匹配训练数据、优化资源、输入信息、模型可用时间、评价器与硬件成本，并报告差异。
- 以真正的独立单元（人、设备、实验日、任务等）分析而非把相关帧数或 seed 当独立组；报告每组效果与适用的区间/效应、负结果以及多任务/多次比较的范围。小样本、欠收敛或只用开发集的结果应写 INCONCLUSIVE 或 EXPLORATORY，而非“显著”。若研究选取过多个任务/切片/模型，明确对应选择范围及主张局限；追加 seed 不会生成新的独立人/设备/实验日。
- 数据泄漏、标签循环、假真值、时钟未来信息、后验选择确认集为严重科研缺陷：隔离受影响结论，必要时重建合法外部验证。历史有效的其他结果不自动全部失效。
- 首次确认负结果不要求项目级 STOP；不能偷改确认协议重试以获得正结果。新的探索属于新版本与新主张。

## 5. Claim→Evidence 表与出口

建议只需一张增量表，复用已有 CLAIMS/STATE：

| 字段 | 填写内容 |
|---|---|
| CLAIM_ID / SCOPE | 当前一句科学主张及限定场景 |
| EVIDENCE_RUNS | 真实完整 Run ID、源码/数据/划分/指标与原始证据指针；负结果与被试过的候选不可删除 |
| TASK_SEARCH_DISCLOSURE | 被探索任务、切片和模型选择的简明范围 |
| BASELINES/NEIGHBORS | 公平简单与具名近邻的对照/缺失说明 |
| INDEPENDENT_CONFIRM | 与当前 task/claim 对应且未参与选择的 holdout、外部独立组/证明，或 CONFIRMATION_UNAVAILABLE |
| UNCERTAINTY / LIMITS | 独立n、CI/效应、训练预算、方法和应用边界 |
| PAPER_READINESS | NO_INDEPENDENT_CLAIM / CLAIM_WITH_GAPS / DRAFTABLE / SUBMISSION_CANDIDATE |

**若缺关键证据**：允许提前写“计划验证的论文草稿”，不能把计划/代理当已验证结果；研究收益、原创性、论文接收和影响因子都不能保证。正式投稿、外传、费用和相应独立确认所需资源仍须真实用户许可。

# 第十章实例｜跨设备 IMU 研究的假想执行路径

> **教学示例，所有数字/结果均未实测，不代表某个真实数据集支持这些结论。** 具体执行前必须换成官方已核来源、真实标签、独立分组和实际用户授权。

**起点（活动01）**：用户只确定“希望提高可穿戴 IMU 在不同人、不同设备上的运动识别可靠性”，选择拥有多个受试者和设备的合法公开数据，尚未明确具体创新机制。初筛核官方来源、设备/群组 ID、许可、标签独立性、大小和至少一个可验证的泛化问题；用户选**问题—数据组合**，不是“选择某个新网络”。

**数据（活动02）**：已获下载授权后获取核心原始文件，逐分片或逐文件核完整性；按受试者及设备设置开发分组与封存确认组，holdout只核存在/哈希。发现真实存在的任务标签/分组问题时记录 OBSERVED；若未经实际读取只能写 HYPOTHESIZED。**此时只保证封存隔离，不预先承诺所有未来 TASK 都能用这批组确认。**

**任务产生（活动03）**：从开发数据观察提出三个可选方向（仅示例，不强制凑三）：
- T-A 跨设备表征是否稳定：与同信息且公平调优的简单模型比较。
- T-B 少量目标设备标定信息是否能改善新设备适应：K-shot、时序/标签可见性、训练和评价分离。
- T-C 是否能预测跨人失败并进行可靠性拒绝：需要与实际错误匹配的独立标签和成本定义。
这不是“一个任务失败之后临时为提分改指标”，而是有来源、可测试的新科学问题。选前保留全部候选与廉价探针结果，不能在封存测试集选任务。

**实验（活动04）**：先用开发数据核样本、时序和公平基线，预算内检查学习曲线/错误残差与正控。假设 T-A 初始方法无改进：不直接判整个方向失败；检查是否为容量/协议问题后，可改任务 T-B（如果其科学价值成立）或继续 T-A 的廉价可学性探索。每项 Run 记录有效分组、方法、成本和相对原始证据，**即使代码回退也保留负结果**；一次弱正增益仍需核组级稳定性。

**收敛（活动05）**：如果 T-B 的开发结果可重复且具名近邻尚有独立价值，就冻结核心科学 Claim、K-shot 和分组设计及公平基线；不能因为 T-B 在三个候选里分数最高就宣称独立确认。若都无收益且问题价值不足，向用户建议更换问题或数据。

**确认（活动06）**：只有获得正式实验授权，且 T-B 的真值、K-shot 校准/query 时间关系、设备/受试者分组与原封存组真正适配，并确认此前未借助 holdout 选择 T-B/模型/超参，才能对冻结方法进行合法确认评价。若 holdout 不适配或已污染，记 CONFIRMATION_UNAVAILABLE，寻找外部组/数据或缩窄结论；不因 T-B 在开发集较好就替换独立测试的任务定义。

**最终示例交付（没有真实实验时）**：
- AREA_DATA：跨人/跨设备 IMU 泛化，PRIMARY_DATA=UNVERIFIED
- TASK：T-B（假想候选）；OBSERVATIONS=NOT_RUN；BEST_VALID_RUN=NONE
- HOLDOUT：UNVERIFIED；AUTH：只读/下载/训练范围待真实核
- NEXT：先确认官方数据与现有权限，再执行一项合法数据/任务判别

这个案例展示**方向先行、任务后生、机制逐步探索、论文严格确认**，没有任何隐含论文成功保证。

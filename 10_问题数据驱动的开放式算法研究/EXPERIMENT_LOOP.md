# 活动 04｜有界算法研发、可恢复实验与自动纠错

## 1. 默认模式：先让真实科学问题变得清晰

开始开发前**不要求完整论文级假说、SOTA复现或所有机制消融**。按当前 TASK 和权限选择：
- DISCOVERY：真实开发数据上观察现象、误差、可见信息和问题定义；只读、拟合训练分别核权限。
- ENABLEMENT：恢复数据读取、同步、标定、形状/时间/分组、评价器、日志、训练稳定性等必要能力；工程验收无需新算法增益。
- BASELINE/IMPROVE：准备宣称性能差异才运行同任务/同输入/同组别的简单可信基线与合理优化；最强近邻正式确认前必须公平比较，缺失写 BASELINE_PENDING。
- MECHANISM_TEST：科学解释或新机制比较时先写 A/B 差异预测、负对照或合成正控；没有真正机制归因需求时不虚构 A/B。
- CONFIRMATORY：只在冻结最终候选和获得相应用户授权后，交 [CONFIRMATION.md](CONFIRMATION.md) 执行。

## 2. 从现象到方法：优先机制差异，不为复杂度而复杂

先判断新方法解决哪类限制：**额外合法信息**（历史、标定、辅助模态）、**同输入归纳偏置**（物理约束、相对/不变表示）、**训练优化**（收敛、损失、均衡）、**容量/工程能力**（同步、数据解析、算力）。若主要目的是恢复有效评价链，先做 ENABLEMENT；若简单强基线已能解决问题，允许以可靠的残差规律、成本边界或任务定义收敛研究，不强迫新网络获胜。新机制只有在需要机制归因时才预写区别于简单解释的 A/B 预测。

**低成本任务选择顺序**：当前可信证据 → 最危险但可判别的 UNKNOWN → 一项开发数据上的最小试验 → 按结果更新 TASK/机制。初期不要求全套对照；准备大额 GPU 扩展或正式科学 Claim 前再核相应更强证据。一次廉价失败不会自动触发全部诊断。

## 3. Agent 一次性中等粒度任务指令（可直接改字段）

**跨平台交接**：ChatGPT 只提供已核证的问题—数据组合、当前 TASK/最主要未知、证据路径（或 UNKNOWN）、下一判别实验和用户真实授权范围；不臆造本地目录、Run 或下载成功状态。WorkBuddy/Codex 首先对照实际 `STATE/manifest/Run` 做**增量恢复**，再继续执行。若发现 ChatGPT 的先验与本地不一致，以真实可复核数据和用户最新授权为准；冲突会影响科研主张或资源权限时先报告。不要为了“交接完整”复制长聊天或所有旧实验。

> TASK：基于最新有效开发数据与代码，解决当前 TASK_ID 中最有信息价值的一个问题。先复用数据manifest/已验证Run；检查本轮权限、冻结协议与确认集。仅按需要读取项目 STATE、相关实现及本文件。给出 `NEXT_PROBE` 的预期可区分结果、最低验收和费用上限；能力修复可以只验功能，不必虚构科研增益。
>
> EXECUTE：在已授权范围连续完成最小真实验证→必要局部实现/修复→公平的最简基线或差异实验→保存原始预测、配置、数据与源码版本→最小相关回归测试。首次合法非训练原型可以先做 shape/mask/时序及真实batch读取；不因缺新机制/强基线增益停止。**只在出现真实差异/关键不确定性时升级实验**，不因算力闲置盲目扩大GPU规模。
>
> CONTROL：固定本轮所用合法开发分组、共同评价器、预测前可用输入、主要指标/分母；允许在开发组上改进，但不读封存确认集、不改变已冻结验证范围、不扩张下载/拟合/GPU/费用权限。
>
> REPAIR：异常先定位第一个真实错误，定向复现→局部修复→验证受影响不变量→自动恢复原任务；若模型本身真实负结果，不强行当成代码Bug。改变标签/划分/时钟/评价器时，只使受影响Run失效并重算，保留其他有效证据。
>
> OUTPUT：实际新增Run/观察及路径、相对公平基线的有效效应/不确定性或 UNKNOWN、修复及验证、使用资源、保留/淘汰的分支和下一最低成本判别；若没执行写 NOT_RUN，不抄全部日志。

**重要授权**：用户只允许无拟合前向/只读时，不可训练 CPU Ridge、tiny-set 过拟合或 GPU 模型；真实训练需要对应授权。CPU/MEM/GPU实际开销按用户批准预算计，源代码中的“已有许可”不能替代真实用户消息。

## 4. 有界实验循环：可记录、可对照、可恢复

1. **读取资产**：最新问题—数据组合、TASK_ID、BEST_VALID_RUN（最佳有效Run）和数据/协议/源码版本；实验不存在时用最低成本可运行观察，别重做已完成实验。
2. **选择下一实验**：优先能区分科学解释或验证实验能力、降低不确定性的操作；合理优化优先于无依据的复杂模型。比较性能时，为基线与候选提供公平的优化资源。
3. **区分修改范围**：PROTECTED = 原始标签/血缘、合法分组、评价器、未接触确认集和用户冻结对象；EDITABLE = 在当前授权和实验合同内的模型、特征、Loss、nuisance 调参。发现标签或分组错误，**不得原地静默修改**；先留存原始资产，再以新 `data_version/protocol_id` 纠正并只重新评估受影响 Run。确认集污染不可通过改名或重划分洗白。
4. **执行可复现 Run**：单独保存原始代码/commit、data/version、split、评价器版本、seed、超参数、状态、预测/指标、成本、raw path。默认保存开发集逐样本/组级预测与评价配置（合法、成本可控时）；训练未成功也要保存失败原因和版本。即使回退代码，**Run 证据与负结果不得被回退丢失**。使用最小可读取日志，避免把完整训练输出倒入上下文。
5. **分类而非一刀切**：KEEP（有效证据支持继续）；IMPROVE（可信但未达目标，下一实验信息增量明确）；REPAIR（有界实现/评价失效）；INCONCLUSIVE（功效不足/欠收敛/有效比较不充分）；DISCARD（该机制或Run不值得继续）。所有决定必须写 DECISION_SCOPE=RUN|MECHANISM|TASK|AREA_DATA。
6. **恢复/预算**：项目级STOP只由外循环依据TASK/AREA_DATA级证据作出；单Run没有收益只能限制受影响分支。有已批准剩余额度且下一实验有价值就继续；预算达到上限或实验不产生信息则 HOLD，说明续做条件。**autoresearch 的无限循环只是参考实验反馈，不移植到本章。**

**续投优先级（不是固定闯关）**：先保护已成立的 `BEST_VALID_RUN`；若只差必要训练能力/可信基线，做短的恢复检查；若存在可辨识的机制差异，跑最小对比；如数据规模/训练时长可能主导结论，才做成对的短/长或小/大锚点；只有这些指向现实收益且授权足够，才增加完整 GPU 训练。每次评估 `新增信息或能力 / 预期总GPU+CPU+Token+人工成本`，不以 GPU 占满或实验次数当进展。**主力方案与挑战方案保持固定可比评价器和输入条件**；出现小幅开发集收益时先核组级方差/重复选择偏差，不能仅凭幸运 seed 自动升级为新主力。

## 5. 负 Pilot 后的按症状诊断选择器（仅选有区分力的一行）

| 当前证据/症状 | 优先的最小行动 | 不能据此推断 |
|---|---|---|
| 基线指标很高、复杂模型无增益 | 开发集配对残差、最强简单替代、能否新增合法信息或改变任务边界 | `Oracle` 参考差距就是可实现收益 |
| 训练拟合差、短 Pilot 无增益 | 梯度/数据正确性、已授权正控、合理超参；必要时同协议短/长训练锚点 | 机制已被证伪或必须无界扩大训练 |
| 训练好而跨受试者/设备/日崩溃 | 合法 group 层误差、时钟/归一化核对、简单校准或不同归纳偏置 | 随机帧切分下的高分意味着泛化 |
| 双模态互补、动态选择不佳 | 额外模态**可纠正性**、动作前**可辨识性**、固定/随机/周期策略成本匹配 | Hard Oracle 或互补错误能自动转成可学门控 |
| 自标定后熵降但任务指标降 | 有真值的已知扰动正控，检查校准参数是否可识别、干预是否作用在正确单位 | 信心增加等于校准成功 |
| 差异很小/组别少/CI过宽 | 核实际独立 group 数、配对效应与可检测范围，视成本补开发组/重复测量 | p>0.05 意味没有科学价值或可无限追加 seed |
| 简单模型优于复杂模型 | 保留简单结果，分析有效机制、可迁移规律及独立贡献可能 | 研究问题失败或必须强造复杂模块 |

**反例优先**：若某个 Pilot 无增益，先问“它的结果有效吗、什么替代解释更廉价、哪个实验能真正改变结论”；若某个 Pilot 有微弱增益，也同样检查公平调参与独立组稳定性。**正收益不自动 KEEP，负收益不自动 STOP**。实验选取优先信息增量而不是最大迭代次数；调参次数、测试的任务/切片及被丢弃 Run 都应留存以便识别自适应选择偏差。

**诊断边界**：正控与容量锚点是按风险选择的工具，不是每个任务必跑的门禁。`INCONCLUSIVE` 可因缺可负担判别试验而 `HOLD`，却不能写为科学 `REFUTED`。比较不同输入、组别、激活成本或评价分母时标 `NOT_COMPARABLE`；失效评价的分数先标 `INVALID`，不能用于决定算法好坏。旧Run未保存逐样本预测可做合法无参数几何诊断，但不能伪称重现原模型预测。

## 6. 区分“无法学习”和“没有训练好”

在合法训练预算内，根据曲线/能力诊断选择是否值得做成对长短训练锚点、真实标签正控、匹配容量基线、分组误差/配对预测。短 Pilot 与欠收敛不能直接推断强机制不可能；低功效不等于效应为零。但反复无信号且成本增加时，要明确止损而不是无限调参。

- 相同组别与输入、相同目标和评价分母才允许做公平提升比较；Oracle使用未来/额外信息只作诊断，不是部署策略的数学上界。
- 传感器时序需核相对时刻、对齐、单位、真实采样率、漂移、train-only 归一化；变化时定向跑数据不变量。
- 简单方法可行就先保留为强资产；新机制需能明确科学价值和性能/条件增量，但早期允许探索不立即提分。
- GPU利用率不是科学 KPI；不能为了填满显存而扩大无信息量实验。

## 7. 自动纠错、缺陷严重度与原任务恢复（复用第八章，不复制完整手册）

先问缺陷**影响当前哪项动作或结论**：`CRITICAL`（已证实泄漏/伪真值/越权/必要平台阻断）只暂停受影响动作并隔离不可信 Run；`REPAIRABLE` 在原授权和预算内自主完成最小复现→根因修复→受影响回归→恢复；`MINOR` 顺手修或记 `DEFERRED_MINOR` 不阻断。`UNKNOWN` 只在影响当前科研真实性/权限/高额不可逆成本时查证，不自动一票否决。科学上真实的无增益不是 Bug，交本文件的诊断与续投决策。

遇到实质故障时按需读取第八章 [TRIAGE.md](../08_算法检验与优化/高水平计算机论文工作流/TRIAGE.md) 和 [RECOVERY.md](../08_算法检验与优化/高水平计算机论文工作流/RECOVERY.md)：`DETECT → DIAGNOSE → REPAIR → VERIFY → RESUME`，先定位首个失效证据，修后只重算受影响版本。**第八章文件仅是共享修复方法，不改变第十章的选题/路由/用户授权**；不得因普通Warning、小缺口或工程PASS而停止/宣称科学成功。原则上将相关小Bug合并一次处理，不逐条要求用户选择；需新授权、实质改题或协议冻结变化才停下请用户决定。

## 8. 分支纪律与 Token 效率

默认为**一个主分支＋按需少量机制竞争分支**。AIDE/AI-Scientist-v2 的树搜索只在明确具备可比较候选和资源时借鉴；没有必要做完整树搜索图、复杂多 Agent 平台或重复代码生成。每个分支记录 parent_run / task_id / protocol_id / changed_scope / rationale / evidence。没有新可学信息时结束本分支；不要拿不断搜索的最优 dev 指标冒充 confirmatory 增益。

**Run 最小日志（可用旧文件）**：run_id | task_id | parent_run | data_version/split_id | code_commit | protocol_id / evaluator_version | train_auth | wall_gpu_time | metric_or_observation | evidence_scope | status | decision | raw_paths。与既有格式字段等价时复用，不强制新增记录系统；关键分支需能从 `task_id` 找到候选历史及受影响的科学 Claim。

**默认输出格式**（尽量短）：完成/NOT_RUN；最佳合法Run与增量证据；重要修复/残余风险；`NEXT_PROBE`（观察/能力恢复/机制判别，预期改变什么决策）及成本，真实授权或预算缺口。论文强证据见 [CONFIRMATION.md](CONFIRMATION.md)。
